# 首个目标启动流程（2026-09-28）

## 对外行为

静止等待 → 保留首个合格候选 → 两张新图像完成一次建库 → 同帧锁定 UID → 独立检查运动条件。

- C0 是“人”类别，不是个人身份编号。首次自动选择要求唯一、主体清晰的合格人体候选；不按最大框或任意框列表顺序挑人。
- 首个合格 raw track 与其外观锚点被保留。后来出现的更大框、多人干扰、短时弱质量都不能静默替换它。
- 两张不同的新采集图像仍检查同一轨迹、外观、位置与尺度连续性。重复/乱序图像不计数；短断档只重建连续证据，不换人。
- 2026-09-29补充：首张尚未确认的姿态发生变化时，允许基于固定首颜色、首几何及有界连续观测重新建立双帧证据；不是永久要求所有新图与首图全身距离<=0.20。详见 [首次姿态接续](startup_pose_recovery_20260929.md)。
- 首次锁定前一律停车，包括人物在边缘、暂时消失、旧配置开启开机搜索。删除原先确认期间的“候选居中转向”。
- 身份银行首次录入成功后，当前正式输出 UID、raw track、检测框、CAP、采集时间需精确对应；携带这个证明的帧直接锁定，不再在控制层多等两帧。旧创建帧即使超时，下一张合格新帧也可传递此身份来源，但不能用旧图像刷新授权。
- 无上述证明的兼容接口仍需控制层新观测确认；深度快环不能负责首次锁定。
- 锁定后固定原 UID。短暂质量不合格只限制当次运动，不重新选人；真正丢失后才执行原目标搜索与 ReID 接回。

## 身份与运动的边界

锁定不是前进指令。距离已在保持范围、没有新鲜深度、身份冲突或危险时仍停车。转向几何不可用但有合格首次身份证明时，可以锁定身份并停车，不把运动资格再变成重复建库条件。

正常跟随、RPM、PI、深度授权期限、丢失接回门槛本轮不改。启动采集年龄复用运行配置 `VISION_CONTROL_MAX_RESULT_AGE_SEC`。旧 `search_before_first_person` 键仅兼容读取，不再允许未锁定时开机扫描；`initial_target_confirm_frames` 仅用于无建库证明的兼容入口。

## 运行层

启动 STOP 必须实际入队，不能被“视觉不拥有纵向轴”的过滤移除。没有活动 UID 时，横向意图与最终旋转执行均不能生成运动；已有深度/横向上下文不能绕过首次锁定。

显式释放目标时撤销运动缓存与旧指令；普通漏帧不清图库。若首个候选尚未完成建库就长时间离开，原始 track 已被删除并换号，本轮不会自动把新人当成原候选。此时重新启动程序进行重新选择；内部 `tracker.reset()` / `IdentityBank.reset()` 同样会清除录入候选，但不能在运行线程外无同步调用。

## 诊断与验证

录像显示 WAIT PERSON、WAIT BODY、ENROLL 1/2、WAIT LOCK、TARGET U… 等阶段；候选 raw track 改变显示 WAIT FIRST CANDIDATE，外观与首候选冲突显示 VERIFY FIRST CANDIDATE。日志 `initial_target_confirmed ... source=identity_enrollment` 表示已使用统一确认。

无硬件测试覆盖真实 tracker → 当前观察绑定 → 控制器锁定接口，以及多人抢占、重复/旧图像、首候选换号、弱质量、开机边缘目标、空帧、深度-only、危险停车、锁定后丢失和运行层 STOP 分流。真实启动耗时仍取决于模型预热、图像质量和采集时效，需要实车复测；离线测试不证明实际车轮响应。

当前帧缺少有效全身特征，或明确记录身份竞争失败时，不能导出首次锁定证明；正式录入路径也不退回到“数两次缓存 UID”来绕过这个条件。已锁后的原映射语义不变。
