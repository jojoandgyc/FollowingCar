# 120RPM起步/追赶请求试验

## 后续配置更新：请求180RPM，60RPM近距上限待标定

用户要求追赶请求180RPM，主INI已更新为pi_launch_request_rpm=180；总上限仍200，
其余机制不变，下面120RPM段落保留为初版方案记录。180RPM理论车速约2.450442m/s。

用户还要求静止目标1.8m时制动允许60RPM。这项没有直接实施：remaining=.27m，
60RPM=.816814m/s，按 v*delay+v²/(2a)<=remaining，零采样龄(delay=.2)需要a>=3.1283m/s²；
采样龄50/100ms分别需5.0701/13.3673m/s²。150ms时仅延迟行程已超剩余距离。
目前模型a=.4（非实测），代码支持最大1.0；即使a=1.0零采样龄也仅允许约41.25RPM。
不能伪造减速度、改小设定距离或在制动后加60RPM下限来实现。须先独立实测刹停延迟与距离，
明确可接受的近距余量，再评估模型；不承诺180请求能够使1.8m实际下发60。

## 目的与边界

用户要求一开始就请求120RPM，由电机控制器处理自身加速过程。本轮不写电机加减速寄存器，
也不声称已经知道实际加速度。只改变distance_pi前进分支：有新鲜可信距离、可靠轮速反馈，
且距离超过设定值+原3cm死区时，将追赶请求提高到至少120RPM，再过原制动包络/总速度上限。
请求不是最低允许实际速度：近距离、快速接近可以降到120以下乃至0；真实失目标/危险/过期仍撤权。

不做定时“54321”，不做持续N毫秒的脉冲，不用旧样本续期。每次合格新测量重算；
误差进入死区后撤掉追赶底额，仍由原PI及制动决定匹配速度/停车，不强制清空积分。
120只是请求下限，PI本身请求更高时保留原200RPM总上限，不能误读为200RPM已实车验证。
原有启动资格、身份与距离质量门控不放宽。

## 实现

- 新增[distance_pid] pi_launch_request_rpm，0关闭，主配置120；旧配置/直接构造默认0。
- 试验启用且符合追赶条件时，跳过软件正向升速斜坡（包括新授权恢复的零时间预算）；
  仍先应用原制动包络。不是取消过期停车，也不改变倒车、转向或电机固件加速设置。
- 反馈不可靠时禁用120请求，沿用原保守控制；无原始相对运动证据但轮速新鲜时，
  仍可计算请求，制动按目标静止假设限幅。没有把估计人速未知当作没有距离。
- 不改P2.0、Ki0.4、250ms前进授权、180ms新控制样本、190ms视觉期限及深度过滤。

## 风险与验证

26cm轮径、周长0.816814m，120RPM约1.63m/s。0.4m/s²只是现有减速模型，
在此假设下静止目标所需减速距离很长，不能承诺到1.6m才刹车。制动上限不足时不会实际下发120。
先用无硬件测试验证0RPM起步、120请求可到达运行时授权、制动可压低/清零、反馈缺失、
重复/乱序/过期深度、授权撤销、倒车与旧模式不受影响，并覆盖生产回调绑定。
测试通过后实车只做有急停的空旷低走速短测，记录真实制动过程，再决定是否扩大测试。

下轮比较：移动MAE/最大距离；>10RPM批准突降次数及原因；零指令占比；
120请求占比、制动限幅比例、请求→批准损失、批准→实测差及响应时间。
身份/深度不合格仍批准前进必须为0次；站定最小距离、收敛时间、反复起步单独统计。
本轮不保证下发一定达到120，也不以取消制动来换取“明显变化”。
回退只需pi_launch_request_rpm=0，原缓存接续/PI修复继续保留。

## 解释实际下发值

用当前纯函数、静止目标、0轮速、新采样(age=0)核验，1.6/1.8/2.0/2.4m时
制动上限约12.47/28.76/39.55/55.69RPM。即使日志total_demand_rpm=120，
这些场景也不会实际下发120。新鲜可靠的相对运动证据会改变上限，不能伪造人速绕过限制。
若请求已经120而批准仍小，下一步应核验制动模型和实际减速度，不再误判成P太小。
主配置P2.0保留，远处PI请求超过120时仍可按原上限批准；120不是总限速。

新增launch指标按UID+sample_ts去重：audited/requested数、升速旁路样本数、限幅原因、
总请求/制动上限/反馈RPM及反馈年龄分布。旧日志没有字段时不把缺失伪装成0。
已有发送与反馈异步日志用于核对实际加速；本轮未新增串口查询或修改电机寄存器。
software_rise_bypassed统计旁路模式生效样本，不等于每个样本都实际减少了一次爬坡。

验证结果：本轮新增49项回归通过；全套2625项通过，原有两项search_direction_switch仍失败，
3条旧P试验警告为预期。新增范围含纯函数、真实绑定/授权/假电机、配置与指标；
编译、启动脚本语法、diff检查通过。未操作实车，响应速度与过冲待新运行验证。
