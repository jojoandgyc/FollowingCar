# 独立深度目标跟踪方案与第一阶段实现

## 结论和当前状态

2026-09-17更新：已接入在线被动观察，见 `depth_track_online.md`。
当前在线几何使用明确标记的未核验配置HFOV/编码器近似，并未完成本文件提出的
相机内外参和时间同步验证；所有输出仍禁止控制。下文保留最初A阶段设计与实现记录。

可以不等待每一张新的视觉框，但不能不确认“深度里的哪一块属于原目标”。
目标是用视觉确认身份与定期校正，用独立深度关联更新位置；不是把旧人体框
长期套到最新深度，也不是将最近障碍物作为跟随目标。

A阶段最初仅完成离线shadow-only原型、回放入口、只读深度历史接口和测试。
现已追加上述在线观察接入，但仍未接管电机，正常运动使用现有测距控制链。
阶段B的标定/实测验证和阶段C控制接入尚未完成，不能把原型通过测试当作上线完成。

## 三阶段及接口边界

### A：先验证独立关联（本轮）

1. 输入确认过的活动UID、真实RGB时间、对齐Depth、可信距离、深度坐标系躯干ROI。
2. 在该距离附近寻找深度连通簇；不能从全图直接选最近点。种子不唯一就拒绝。
3. 从历史种子帧开始，按物理时间顺序补处理缓存深度，追到最新帧。
4. 每个新Depth：常速度预测世界位置 → 用该帧相机位姿变换回相机坐标 → 投影
   搜索窗口 → 深度带连通域 → 面积、位移和深度连续性过滤 → 唯一候选才更新。
5. 输出UID、相机三维位置、世界位置、视觉锚点时间、物理深度时间、候选数、拒绝原因。
   `control_allowed=false`、`motor_authority_created=false`始终成立。

当前算法是保守的连通域+常速度原型，不是成熟人体分割或Kalman滤波器。
人体孔洞可能分裂为多个簇，人与墙接触可能合并，同深度人物交叉仍可能误关联。
唯一连通簇不是身份证明；任何一次关联失败都要求新的视觉种子，原型不自行恢复。
稳定关联经过验证后再增加掩码形状/多区域证据与滤波，不先隐藏观测误差。

### B：在线被动验证（下一阶段）

- 独立worker读取有界Depth环形缓存，不持有视觉/控制锁执行聚类；只发布诊断快照。
- 图像拷贝、CPU时间、记录量有上限；超负荷丢弃诊断工作，不阻塞主控制。
- 种子必须来自主视觉已确认UID，保留原始YOLO框、身份事件代次及对齐时间。
- 相机位姿需由已有IMU/编码器历史插值，处理左右符号、轮径和相机到车体外参；
  数据缺失不得默认为车体静止。必须记录姿态年龄及不确定性。
- 首先校验左右/中心时Depth与RGB对齐、深度图内参、畸变、拍摄时钟。
  当前Astra时间戳是在`read_frame()`后记录的到达时间，不是真正曝光时间；
  原型输入pose时间对齐通过不代表已经完成设备时钟标定。
- 对比原测距与新跟踪，只记录，不修改主距离滤波器、身份库、搜索方向、PID或轮速。
- 优先覆盖单人靠近/远离、差速转动、近距离裁切、多人交叉、贴墙、黑衣无效深度、
  短时遮挡、目标离场及重捕获。已有异常快照是稀疏样本，不能伪装成连续30Hz回放。

### C：受限授权（验证后）

每个新鲜且连续关联成功的Depth可以独立刷新纵向测量，不要求同时有新YOLO框。
由一个仲裁入口合成纵向基速和横向修正，交给现有50ms执行器；跟踪器不直接发电机。

| 时钟/状态 | 作用 | 禁止的行为 |
| --- | --- | --- |
| 视觉身份锚点 | 周期性验证还是原UID；原型上限350ms，仅供shadow实验 | 新Depth不能续期身份 |
| 新鲜Depth观测 | 180ms内且实际关联成功才可成为后续纵向授权依据 | 预测值/重复帧不能当新测量续期 |
| 执行截止时间 | 从物理Depth时刻计算，不从下发时刻计算 | 50ms调度不能延长安全期限 |
| 视觉确认失目标/UID变更/搜索 | 撤销该事件的跟踪状态 | 深度不得创建UID或解除搜索 |
| 歧义/关联失败/危险 | 撤销新跟踪授权，安全降速或停车 | 不能猜一个人继续追赶 |

350ms身份锚点窗口不是将现有电机180ms TTL改成350ms。在线控制接入时还要确认
允许的自主持续时长和置信区间，当前不更改任何运行期限。历史补帧只能补状态估计，
不能补发过去的动作；只有追到当前且仍满足全部期限时才有资格申请控制。

正常跟随短时失去前进授权时，下一步需要防止自动转成反向轮速的原地旋转：
以受限减速/停车为优先，不能沿用“基速归零后照常叠加轮差”而反复触发过零等待。
明确搜索状态仍保留自己的旋转规则。真正反向轮速仍必须保留实测过零保护。

独立近障安全路径可以另行设计，但它回答的是“是否有危险”，不是“目标是谁”。
深度近盲区/全零不能被当作空旷，也不能仅因一张深度图变远就自动恢复前进。

## 验收指标与基线

本轮基线`run_20260916_165638_16135_4f45e0b0`，CAP1017–1325：

- 采集时间16.49s；距离1.723→3.135m，漂移+0.086m/s。
- 已选目标距离缺失19/120=15.8%；有效距离8.3Hz；22次深度间隔>180ms。
- 零轮速指令时间占比33.6%；时间加权指令基速25.3RPM；无匹配基速40.6%。
- 36条过零等待，其中12条存在新鲜深度与正向请求。

阶段B观察指标：符合输入条件的物理Depth帧关联率、独立更新Hz、处理耗时P50/P95、
队列丢帧、视觉/深度/位姿年龄、轨迹连续时长、原因分类、人工标注错绑率。
初步工程目标是处理P95<15ms、合格物理帧关联率>80%；不是已实现的性能承诺。
验证集任何已知身份错绑都须先定位，不能用平均有效率掩盖。

阶段C才观察实际连续轮速、停车响应、过零等待时长、50ms周期抖动、速度前馈掉档、
距离误差均值/P95和漂移。用相同路线/人速/起始距离做A/B；速度上限先不提高。

## 离线回放用法

`python3 tools/depth_track_shadow_eval.py /path/to/manifest.json`

stdout每帧JSON，stderr原因计数；不打开设备、不生成动作、不写身份库。
每个npz须有uint16、毫米单位的`depth_mm`。下例内参/位姿仅用于说明格式，
**不能复制为Astra标定值**；躯干ROI是深度网格坐标，不是放大后的DeepSORT框。

```json
{
  "schema_version": 1,
  "depth_geometry": "registered_rectified_orientation_verified",
  "intrinsics": {"width":160,"height":120,"fx":140,"fy":140,"cx":80,"cy":60},
  "frames": [
    {
      "frame_id":1,"depth_file":"frame1.npz","timestamp":10.0,"observed_at":10.15,
      "active_uid":1,"pose":{"timestamp":10.0,"x_m":0,"z_m":0,"yaw_rad":0},
      "anchor":{"uid":1,"visual_timestamp":10.0,"torso_bbox":[60,30,100,90],
                "trusted_distance_m":2.0,"identity_confirmed":true}
    },
    {
      "frame_id":2,"depth_file":"frame2.npz","timestamp":10.033,"observed_at":10.15,
      "active_uid":1,"pose":{"timestamp":10.033,"x_m":0,"z_m":0,"yaw_rad":0}
    }
  ]
}
```

pose为深度帧时刻的相机平面世界位姿（右转正、米/弧度）。显著俯仰、横滚和机架
振动不在当前平面模型能力内；实际场景如有这些运动需扩展SE(3)或拒绝观测。
旧日志没有完整的这些输入，因此这轮只报告合成测试，不报告虚假的实车回放成功率。

实现文件：`depth_track_shadow.py`，`tools/depth_track_shadow_eval.py`；
`AstraDepthRuntime.copy_depth_history()`只提供独立只读副本，不触碰现有测距锚点。
未接入调用方时，不增加采集线程工作和内存复制开销。

验证：新增25项无硬件测试通过，完整回归1492通过；原有2项搜索方向测试仍失败
（`test_current_left_candidate_overrides_right_history_on_search_entry`、
`test_edge_target_crossing_aimline_still_turns_toward_bbox_center`）。编译检查通过。

三维投影依据：[OpenCV相机标定与三维重建文档](https://docs.opencv.org/4.2.0/d9/d0c/group__calib3d.html)。
连通域唯一性、窗口和期限是本项目实验策略，不是该文档保证的人体身份识别能力。
