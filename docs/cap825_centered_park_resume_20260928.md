## 根因

当前使用距离 PI、`pi_launch_full_error_m=0.5` 和正常加速斜率。
驻车预览不积累执行时间，这是正确的：不能把停车时间当作加速信用。
但因此驻车零轮速下，每次 PI 的加速起点和可用时间都是零，执行输出也始终为零。
正常居中控制的 1RPM 占位值在 200RPM 百分比刻度下同样向下取整为 0%。

恢复入口原先只查看动作是否有非零速度，于是形成循环：

`驻车 → 预览执行输出为零 → 没有非零前进动作 → 不能退出驻车`。

现有测试分别覆盖过“驻车 + 旧的不收敛启动下限”及“渐变启动 + 正常行驶”，
但没有覆盖“渐变启动 + 居中驻车”的组合。

## 修复边界

1. 增加只读 `parked_forward_resume_demand_rpm`：仅从当前 UID、当前物理样本、
   新鲜可信深度及驻车 PI 预览中提取**已经经过制动包络限制**的前进需求。
   不使用未经限幅的 P 或启动下限，不向上取整微小需求。
2. 该需求只允许申请解除普通驻车，不直接写动作、轮速、PID 时钟或深度授权。
3. 原有新视觉帧、已完成停车、驻车电流释放、反馈时效和安全检查继续生效。
   非向外运动不会因此绕过普通停车保持时间。
4. 解除后同一张预览依然输出零，不能成为前进授权；后续新样本重新建立正常
   加速时钟，再由统一轮速执行器执行。居中横向输出不变。
5. 不修改 PI 增益、转速上限、180ms 新授权要求、已有 250ms 有界继续期限、
   身份识别、深度采样和搜索策略。

新增日志 `near_yaw_park_resume_demand` 包含 UID、CAP、物理采样时间、制动限幅后需求、
预览执行输出、是否解除，并明确记录 `motion_authorized=False`。
轮速授权仍以随后的 Depth 提交记录为准。
