# CAP1161 身份接回交叉检查

## 本次改动

- 正常绑定目标通过现有质量、外观、几何和更新周期检查后，同步刷新近期 OSNet 躯干模板。待确认、弱质量、接回隔离期间不学习；躯干更新仍受自身更新阈值约束。
- 搜索接回和接回隔离期间，全身授权距离不得优于近期全身证据。例如历史模板 0.144、近期模板 0.220，只能按至少 0.220 判断，不能升级为单帧强匹配。
- 躯干证据分为 match / mismatch / unknown。只有新鲜、质量合格的当前躯干与可用近期躯干比较，才构成支持或矛盾。未知不等于反证。
- 超过现有短时接回窗口（本配置 0.35 秒），以及接回隔离期间，需要可用近期躯干支持。缺失则继续待核验，不赋予跟随资格。没有增加新的固定等待秒数。
- 可靠躯干矛盾清除候选确认链并拒绝本次控制；低全身距离不能豁免躯干聚合失败。已有几何矛盾、竞争检查和模板隔离保留。

开关：`[identity_bank] template_crosscheck_enable = true`，经配置加载器、视觉管线、Tracker 传入身份库。设为 false 可关闭本次交叉检查；之前的模板老化、几何矛盾保护不因此关闭。本次没有修改 RPM、PID、深度授权时限或搜索旋转策略。

注意：躯干使用现有 ROI，并非新增人体关键点/分割模型。可用性检查是质量启发式，不能保证人体部位始终对齐。相同 OSNet 的全身和躯干误差也可能相关，不能称为独立可靠身份证明。

## 离线诊断工具

`tools/audit_reid_crops.py` 默认只读日志；显式 `--infer` 才重跑保存裁剪。发现小车主程序运行时拒绝推理，每张裁剪前再次检查，避免常见的并行资源争抢。它不是操作系统级资源隔离，应在小车停止运行后使用。

```bash
python3 tools/audit_reid_crops.py \
  --run-dir run_request_0428_modular_logs/run_20260921_160853_30544_c5137d24 \
  --templates 562,932,983,997 \
  --queries 1160,1161,1164,1166,1167,1186,1198,1199 \
  --negative-caps 1160,1161,1164,1166,1167,1186,1198,1199 \
  --infer --replay-policy --output calibration/reid_crosscheck_new.json
```

输出包括模型/裁剪哈希、输入格式、纯 OSNet/颜色/融合/躯干距离、模板来源及策略对照。拒绝覆盖已有输出；同一 CAP 多张裁剪时拒绝静默选取。

支持 `--reference-onnx /path/to/same_weights.onnx` 比较相同预处理下的参考输出。当前未找到可验证同源的参考权重，因此**没有完成 RKNN 与参考模型的转换精度验证**。不能用另一份训练权重直接归因 RKNN 转换错误。
