# 授权、执行历史及身份接续的边界修复

本轮对应代码复核发现的五项问题。只修改软件、运行假时钟/假电机回归，未启动
跟随程序、相机、串口或实车。未调整 RPM、PID、ReID 阈值或深度授权期限。

## 新授权与旧授权分别处理

新深度在开始处理时满足 180ms，不代表发布时仍然满足。普通新授权和借助已执行
指令恢复的授权，现在都在发布前重新检查物理采样时刻及派发余量。只有后者额外
核对执行回执；250ms 仍只用于有界延续已经批准的原授权。

回归包括：无任何旧授权时，175ms 样本经过 6ms 处理后不能产生首次前进；
180ms 两侧、派发预算两侧、倒车较短期限，以及原授权的固定截止时间。
若只是普通新样本错过发布窗口，而同 UID 的旧前进授权仍独立合法，则复用既有
晚到深度分支，仅按新观测收紧旧授权；不更新时间、运动依据或批准上限。
近距、危险、身份变化、反馈缺失和执行回执失败不享受该接续。

## 最终写出前的检查不能再次阻塞

直接发送路径原来可能在最后一次授权读取的诊断日志中耗尽期限。例如读取时
249ms、日志耗时 3ms，仍写出了 60RPM。现在在正常跟随实际写出前，以纯内存
检查重新核对物理截止时间、当前 UID/采样来源、批准上限和前馈到期后的限幅。
不重复进入可能写日志的授权读取函数；实际写出前不加日志、串口读取或等待。
周期发送与直接发送共同覆盖；零速度不被这道正向授权检查阻拦。

## 其他电机写入打断旧减速证明

执行历史仍只是制动预算，不是运动资格。现在核对真实后端回执对象和连续序号。
倒车、其他写入或 STOP/模式变更介入后，历史速度成本保留到原有截止时间，
但旧低速指令不再有资格累计减速证明。只有新的正常跟随低速指令实际完成后，
出现两张合格的新反馈，才可退休它之前的高速度预算。

回归使用真实发送函数与假后端：50→30RPM，中途 60RPM 倒车，再转回 30RPM，
不能利用倒车前已经累计的反馈把预算直接降到 30；额外覆盖同值写入、STOP、
同内容不同回执对象及序号断档。原授权的时间和冻结预算不因此改变。

## 身份拒绝不等于清除已耗尽的窗口

姿态接续拒绝时，仍删除旧的正向身份证明；另行保留仅含已消费采集编号和时间
的限制记录。普通边缘匹配不能凭这一帧重新开始姿态/尺度接续窗口。
只有更新鲜、独立且通过身份判断的精确区域证据，或原有规则允许的独立学习，
才能解除该限制。重复/旧帧、拒绝帧不能解除；身份重置/移除清理对应记录。

待复核身份不能通过姿态/尺度保留分支结束复核；配置缩短到 180ms 时也不再
借用旧 250ms 回退。独立证据在原期限内重新通过，仍可正常恢复。

这些修复证明了边界分支的行为，并不能证明实车的卡顿、转身接回率或制动距离
已经达到目标。需要同场景后续日志验证，不能把假后端输出当作实测轮速。
