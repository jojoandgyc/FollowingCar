## 实施

正常配置 `[lateral_intent] follow_cross_brake_enable = true`，
经 `FOLLOW_CROSS_BRAKE_ENABLE` 绑定到真实 ActionRuntimeConfig。
库默认 false，rotation-only 配置不启用；设为 false 可回退旧零速等待。

1. 正常可见跟随的执行层判断确有反转等待时，发送一次 NORMAL stop。
   这不是反向 RPM 脉冲，也不授予前进。等待期间仍读取现有反馈缓存。
2. 由后端保留这一特定 NORMAL 的零速保护。周期零速、forward(0)、
   FOLLOW20_REVOKED 等零包不会切回速度模式；诊断记录 held、packet_written=False。
   当前通过上层资格验证的非零指令可释放；其他显式停车优先覆盖。
   串口部分写入失败时撤销“仍已驻车”的假设，允许后续安全清零。
3. 原来的两次新停稳反馈继续有效。增加可见原地转向的另一种放行证据：
   两轮连续两次新反馈已经与**当前**请求同向、且未超过当前请求转速。
   避免轮子在两次采样之间越过零点后仍死等恰好零速。
   同一缓存不重复计数；旧/未来/不可信反馈、超过150ms的确认间隙、
   再次反转或反馈超速都不能提供确认。搜索/关闭开关保持旧规则。
4. 等待期间新深度允许安全前进时，沿用已有的前进交接规则，
   只执行最新批准的左右轮请求，不重放旧原地转向或旧高前进速度。
   真正整车反向仍需新反馈确认。读取反馈后再次检查横向期限；
   UID、状态、纵向期限及周期轴状态的原有写前复核保留。
5. 250ms 等待超时只标记问题，不能强行放行反转。
   相比旧版，物理动作由“不断发0RPM”改为“保持NORMAL制动”，
   并不承诺硬件必定在固定时间内停稳。

未新增串口读取、线程、主动休眠或电机加速曲线；仅在真正交接时使用既有停车命令。
后端已有的停车清零延迟配置不变。未操作实车。
