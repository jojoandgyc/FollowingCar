# 独立深度跟踪在线旁路（2026-09-17）

## 实现状态和明确边界

已将独立深度关联原型接入正常运行的后台观察线程。不会修改UID、身份库、搜索方向、
原测距滤波器、PID、电机动作或授权截止时间。没有任何控制模块读取旁路结果。
本轮没有打开相机、串口或执行实车动作；不能宣称实际30Hz关联成功或距离误差下降。

重要限制：没有找到已核验的配准深度内参和相机外参。在线实验显式使用配置HFOV、
方形像素、相机位于轮轴的近似模型，编码器推算平面位姿，不假装是IMU测量。
每条记录均标记 `geometry_verified=false`、`control_allowed=false`、
`motor_authority_created=false`。这些结果只用于发现算法/调度问题；在完成配准内参、
相机外参、时间同步和错绑验证前，不具备接管电机的资格。
深度时间沿用OpenNI读取后的到达时间，不声称硬件曝光同步。

## 数据流

1. 原视觉发布已绑定UID的原始检测框时，仅把不可变观测引用送入旁路；不拷贝RGB。
2. 后台从Astra历史读取最多4张新深度，try-lock失败直接跳过，不阻塞控制或采集。
   在锁外复制并缩采到约160×120，保留16张小图。绝不反向写入原深度。
3. 原测距仅在真正接受新原始距离时发布只读标量 `(UID, sample_ts, raw_m)`，
   不把保持值/候选值伪装成可信种子距离。
4. 为每个新视觉锚点选择40ms内的历史深度。种子距离提示必须同UID，与种子深度
   相差不超过180ms；只是深度带搜索提示，实际簇距离从种子图重新测量。
5. 使用已存在的无锁编码器缓存，以物理反馈时间积分位姿，深度时刻必须有前后反馈
   插值包围。不能拿“没有反馈”当静止，不能外推。反馈不可信/过期/跳变或间隔
   超过120ms会切断位姿历史，旧坐标系下的轨迹不能继续使用。
6. 从种子按时间顺序关联到最新深度。连续新Depth可以更新位置，不要求新的YOLO框；
   重放旧图仅补估计状态，不能增加实时帧数。相同物理样本不会重复计算有效更新Hz。
7. 新深度不续期视觉身份：锚点固定350ms、实时深度180ms；都仅为旁路观察预算，
   不改变原控制授权。目标缺失/搜索/低质量/身份变化撤销旁路。单纯过期视觉结果
   不立即撤销旁路身份锚点，但仍受350ms约束，原来的电机撤销逻辑完全保留。
8. 关联失败需要新视觉种子；处理期间视觉状态变化则丢弃这次输出，不能写成有效观察。

不增加等待控制的锁、不新增串口读取、不重复运行YOLO/ReID。不修改OpenCV全局线程数。
线程隔离不代表无资源竞争：耗时超过15ms会记录；每次工作后至少休息10ms，重载时
延长休息，绝不忙循环追赶。后台文件写入有32MiB文本上限和12张缩采深度快照上限，
每两秒最多一张快照。已有输出目录不覆盖，观察失败只退出旁路线程。

## 运行与关闭

正常原命令 `./run_request_0428_modular.sh` 即启用在线旁路（需Astra和FOLLOW_LOG_DIR）。
这仍是正常实车程序，会按原控制逻辑驱动电机，不是相机专用命令。

本次运行目录新增 `depth_track_shadow/`：

- `manifest.json`：几何近似来源、轮周长、观察期限、禁止控制声明。
- `observations.jsonl`：UID、视觉CAP、物理深度时刻、原测距样本、实时/重放分类、
  距离、图像中心、簇尺寸、等待/失败原因、处理耗时与潜在测距断档补齐。
- `sample_*.npz`：限量缩采深度图及元数据，便于配合RGB录像检查是否跟错簇。
- `summary.json`：正常结束时的计数；异常退出时可能只有部分JSONL及主日志错误。

停止实验：`FOLLOW_DEPTH_TRACK_SHADOW_ENABLE=0 ./run_request_0428_modular.sh`。
不需要调整P、速度上限、1.5m设定或原180ms电机安全期限。

离线统计（不打开设备）：

```bash
python3 tools/depth_track_online_metrics.py /path/to/current/run_directory
```

| 指标 | 口径/目标 |

| 错绑 | 联合快照和对应视频人工核查；任何已知错绑先定位，不用高有效率掩盖 |
