# 纵向跟随：匹配速度、距离追赶、动态减速（2026-09-17）

## 本轮解决什么

正常跟随的目标是连续生成一个前进轮速：**可信匹配基速 + 距离追赶分量**。
不是正弦/余弦 PID，不是一直200RPM，也不是到固定1.6m才刹车。

实施范围只包括正常前进速度参考、与它对应的下游追赶预算、诊断和测试。
替换原前进 `20RPM起步偏置 / matching + P + I + D` 的计算，避免重复叠加；
原 PID 仍用于倒车及关闭新模式后的兼容路径。保留估计器本身、恢复流程、
50ms执行器、横向差速、搜索/ReID、障碍停车、真实Depth180ms期限。
独立Depth跟踪仍然只是shadow，不因本次速度计算改造获得电机权限。

## 计算链

1. 原流程检查同UID、可靠关联、独立新鲜Depth、危险状态。旧/保持样本不能重新计算新参考。
2. 现有速度估计器提供合格匹配基速；不合格时使用有界距离控制，不伪造目标静止或续用过期速度。
3. 设 `s=max(0, 实测距离-设定距离-死区)`，追赶需求 `min(k*s, catchup_max)`。
4. 提前减速使用两种约束的较小值：
   - 指令接近速度上限满足 `v*T + v²/(2*a) <= s`；
   - 实测接近速度 `c` 在延迟内消耗距离，附加上限 `sqrt(2*a*max(0,s-c*T))`。
   - `T=深度样本实际年龄+配置的执行/响应预算`。
   - 修订：运行链的 `c=max(0,-原始Depth短窗变化率)`；同UID、真实采集时间、
     编码器时间对齐并减去转动引起的Z变化后，在最长180ms短窗拟合。
     不再把中位/融合距离的阶跃差分当制动速度。预热/未经验证的转动时使用
     实测车速的保守接近参考（缺反馈按总速度上限），不能启用新的60RPM预算。
     原始速度异常则单独触发保守制动；近距/危险/过期保护不依赖短窗等待。
5. 剩余追赶速度乘 `60/轮周长` 转为RPM，再加合格基速。前进积分清零，不叠加旧I/D。
6. 加速斜率、总上限、恢复及安全仲裁继续生效；减速平滑不能将输出抬到新制动包络之上。
7. 匹配证据到期，使用同一次计算缓存的无匹配参考；不能重新加20RPM，不能重复积分或续期。

状态名称仅是当前计算的诊断，不新增等待计时器：
`catchup`（追赶）、`decelerating`（提前减速）、`matching`（距离到位匹配人速）、
`distance_only`（无合格匹配估计）、`stop`、`too_close`。

无匹配证据时：未启动仍超过目标+0.08m才启动；已启动允许按新曲线低速接近，
到目标+0.03m停止，不在低于目标+0.08m时提前重置整次前进。人体在走、匹配证据
可信时，距离到位仍可持续匹配；更近和倒车策略不放宽。

## 本轮参数与回退

主 `reid_runtime.ini` 的 `[distance_pid]`：

```ini
approach_enable = true
approach_gain_per_sec = 1.0
approach_max_catchup_m_s = 0.60
approach_deceleration_m_s2 = 0.40
approach_response_delay_sec = 0.20
approach_no_matching_max_rpm = 60.0
```

保持距离仍为1.5m；用户改 `[distance] target_distance_m` 即可平移距离带。
轮周长复用0.816814m。有匹配时追赶上限0.60m/s对应约44.1RPM，匹配上限80RPM及总上限200RPM不变。
无匹配且原始深度接近速度可靠时，独立距离追赶预算提高到60RPM，不计作匹配基速。
60是远处目标请求，不是最低转速：假设深度年龄50ms、接近速度0，距离3.0m请求60RPM，
2.4m约54RPM，2.0m约35RPM，1.6m约5RPM，1.53m归零；真正下发还受斜率/安全授权约束。
关闭这项试验可将 `approach_no_matching_max_rpm=0`，恢复原距离追赶预算。
新模式的编码器接收范围与指令预算一致：80+44.1+5RPM容差，约129.1RPM，
避免正常请求超过105RPM后又被旧反馈阈值清掉匹配基速。不是放行所有200RPM反馈；
超过该预算、过期、不可信和转向异常仍受原保护。回退旧模式时仍为原105RPM范围。
下游原“matching最多加20RPM”改成允许已经请求的上述追赶分量，不是新的速度下限。
新的采样门控不允许凭hold重算速度；正常重复帧在已有runtime保留路径内处理。

以距离2.0m、设定1.5m、暂未进入减速约束为例：

- 旧P24产生12RPM距离修正（不含旧I/D）；
- 新曲线产生 `(0.5-0.03)*60/0.816814≈34.5RPM`；
- 若匹配基速40RPM，请求约74RPM，而不是旧52RPM；仍需通过下游实际批准。

新模式**不使用前进P试验或5/10RPM偏置试验**，启动日志明确标记，避免混淆实验。
倒车仍使用既有PID参数。回退只需设置 `approach_enable=false`，原P/I/D继续有效。
本轮未修改 `aaa.sh`、其它启动器或rotation-only配置；原命令
`./run_request_0428_modular.sh` 会加载主INI的新模式。

## 制动假设和不能承诺的部分

0.40m/s²不是实测标定，更不是安全刹停能力保证。应在空旷场地、有人急停的条件下，
先实测不同轮速的停机响应及滑行距离；硬件若更弱，必须降低减速假设/运行速度。
车轮打滑、滤波滞后、目标速度误估、人物突然停止都影响结果。输入是相机前向距离，
不能把它误当始终准确的世界人速；原转向补偿和置信度限制继续保留。

尤其是：若以0.6m/s匹配人速，在1.5m处人瞬间停止，假设车体减速只有0.4m/s²、
执行延迟150ms，即使立即请求零速，理想模型仍前进0.54m。**仅凭相对速度包络，
不可能同时保证任意人速的1.5m跟随和骤停后仍不低于1.4m。** 后者必须以实测制动、
限定人速/停止过程和独立安全策略为前提；不能靠调曲线消除惯性。

本轮不删除深度过期停车，不接入未验证的shadow，不声称已修复测量断档或全部速度估计退出。

启动应出现 `Longitudinal approach profile enabled ... forward_pid_replaced=True`。
每个物理采样新增 `longitudinal_approach`：UID、sample_ts、mode、距离/目标距离、
匹配基速、追赶RPM、请求RPM、包络RPM、接近速度、预计减速距离、响应预算、无匹配参考。
沿用 `depth_linear_limit` 请求/批准RPM和最终轮速反馈，不能把请求当实测。
兼容日志名 `distance_pid` 在新模式里P字段表示实际追赶分量，I/D为0；先按approach模式区分。

`tools/follow_metrics.py` 增加 `control.approach_profile`，按UID+物理时间戳去重统计状态、
追赶分量、减速距离，旧日志返回0项而不伪造启用。现有MAE、掉速、零指令、缺测指标不改变口径。

## 无硬件验证

测试覆盖单位换算、前进PID替换、同速匹配、静止停止、接近速度制动、样本年龄、
加速/减速斜率、重复观测去重、旧匹配撤销后的无偏置回退、权限保护、下游预算和配置。
理想模拟包括已知静止目标+150ms执行延迟和已知匀速目标；不模拟身份误匹配和真实深度噪声，
不能当作实车性能证明。另明确保留“目标瞬间停止仍有不可消除惯性行程”的边界测试。
