# CAP1194–1262：普通驻车交接与 PI 恢复

## 原因与边界

本轮基线为 `run_20260921_213511_63131_e63d8c0a`。CAP1212 已产生约52RPM纵向请求及−10RPM横向修正，但普通驻车等待双轮≤1RPM、连续安静反馈及安静后采集的新图像，直到CAP1248才释放，记录保持2593ms。驻车期间反复报告无前进授权，又与 `brake_evidence_recovery` 的零加速预算叠加。

此次仅修改普通 `near_yaw_park` 到同UID新运动的交接，以及这段驻车的PI状态。没有修改转速、PID参数、ReID、搜索交接策略或深度授权期限；没有操作实车。

## 实现

1. 普通驻车收到新的、可信、同UID运动请求后，不再等待停车抖动消失。仍要求首次NORMAL写入成功、图像在该次停车写入后采集、图像新鲜且序号前进、双轮反馈新鲜可信、无危险或其他停车占用。横向释放仍要求离开中心释放带。
2. 释放的是普通驻车占用，不是运动授权。纵向仍检查可信深度，轮速执行器仍检查实际运动方向；双轮确实反向等情况继续走现有过零保护。搜索/身份交接仍使用原来的安静确认路径。
3. 首次NORMAL停车保留原序列。相同驻车事件的周期刷新只发送NORMAL，不先写双轮0RPM，不重置停车事件时间；过期的驻车刷新不能重新占用已释放的状态。急停仍走原停车序列。
4. 控制器显式收到普通驻车状态。驻车期间新深度可计算 `parked_preview`，用于判断新的运动需求，但不积分、不积累执行加速预算、不将其当作已执行速度。当前制动包络仍约束预计算请求。
5. 释放时撤掉驻车预计算的执行记忆与恢复标记，不恢复旧授权。新鲜距离通过现有授权检查后，重新接续运动。同一物理样本不重复积分或刷新测量时间。

日志新增：

- `near_yaw_park_motion_check ... quiet_required=False wheel_reversal_guard=preserved`：普通运动交接检查。
- `distance_pi_parking ... active=True/False`：真实控制器的驻车入口/退出。
- `distance_pi ... status=parked_preview`：非执行速度，不应统计为已下发轮速。
- `LZ30EMA 驻车刷新 ... pre_zero=False`：不切入速度模式的NORMAL刷新。

## 下轮验收

仍运行原启动脚本，标注明确的目标移动与站定CAP，并分别统计：

| 指标 | 验收方式 |
| --- | --- |
| 同UID可信运动被驻车静止门槛拒绝 | 普通交接中应为0；不能再因 `wheels_still_moving` 等待数秒 |
| 首个合格运动请求到驻车释放 | 应在同次视觉处理内完成；反馈缺失、危险及旧图像单独计数 |
| 驻车期间有制动余量却因恢复预算输出0 | 不再出现CAP1248式重复零速恢复；真正制动为0单列 |
| 驻车刷新附带速度写入 | 应为0；首次停车和急停不计入 |
| 新请求到实际非零轮速下发 | 分开驻车释放、过零等待、执行调度/串口耗时，不能只看PI请求 |
| 横向执行 | 对比请求轮差与实际双轮归一反馈，确认目标偏离时确实差速修正 |
| 移动距离误差和零指令占比 | 与同场景基线比较，不把目标静止期间的合理停车混入 |
| 站定过冲、反复起步 | 不能为了快速解除驻车引入持续反打或明显近距离过冲 |

这些是待验证标准，不代表实车已经达到。取消普通驻车的安静门槛不等于忽略所有编码器反馈，更不代表原有执行层反转等待必然消失。
