# 180ms制动切换：有界相对运动接续试验

本文件保留首次试验的设计与数值。后续实测暴露的提前失权回归、编码器150ms预算、
已发送指令的物理速度预算修正在[01:48轮回归修复](stutter_regression_014822_20260930.md)；
以下100ms、混合接近速度的B定义属于首次版本，不再代表当前相对模式。

## 目的与授权

用户允许一定接近过冲，要求改善前进卡顿。本轮没有把此许可解释为取消制动。
目标距离仍为1.4m；新增计算余量0.20m，模型停止参考为
`max(目标距离−余量, 既有倒车启动距离, brake_distance+0.05)`，当前约1.2m。
这是试验计算参考，**不是实车一定停在1.2m外的保证，也不是新增硬停车距离**。
新深度已经测到目标距离附近时，仍走原减速/停止逻辑。

未改：250ms物理深度授权期限、180ms新样本门槛、身份策略、驱动器寄存器、
电机绝对上限、PI增益、近距倒车条件、红外/危险/显式停车保护。
未启动现场程序、摄像头、串口或电机。

## 改动

### 冻结本次观测的运动证据

`DepthLinearTiming.continuation_motion`绑定UID和物理深度时间。
仅本次PI实际采用的`RawDepthMotionEvidence`可以进入；要求样本时间、距离变化率、
运动窗口、UID和PI结果一致。FF先验、速度记忆、后来的PID结果、重复/晚到帧不能补权限。
旧授权仅继承原对象，原截止时间不变。

### 一条授权从批准至截止使用连续限幅

有上述证据时，读端在0～250ms始终调用同一相对运动包络，
不在180ms突然切为静止目标模型。限幅只是原批准速度的上限，不增加PI需求。
没有完整运动证据时保留原静止模型，不能猜测目标仍在走。

令`B`为冻结的原速度上界（批准速度、左右实测轮速及接近速度中的保守值），
`t`为距深度采集的年龄。正向目标速度证据按`max(0, v_target−2t)`衰减；
负向速度不抬高到0。2m/s²是明确的模型假设，不是人体运动保证。

过去闭合距离按`max(0, B−v_target_bound)×t`扣除，
另保留固定100ms反馈预算`B×0.10`及2cm余量。
不能以当前较低命令重算过去路程。未来响应及相对闭合制动单独计算。

左右轮仍须可信、≤100ms、正向且不超原绝对上限；
车体平均速度不能超过原B，较快外轮的相对闭合动量须独立满足模型。
目标运动证据只改变制动计算，不可跳过这些检查。

固定授权下，衰减目标速度非增、已消耗距离非减，因此正限幅随时间非增。
新轮速仅能否决，不能提高正限幅。任何归零/身份/反馈否决仍锁住原UID+时间，
不能仅靠下一条正常反馈复活。250ms到期立即失去前进授权。

### 发布与执行一致

首次包络限幅降低速度时，将实际批准值反馈给PI，原B不随之降低。
首次就被否决时清除正动作与授权，标记本次PI请求未获执行资格，
不把坏反馈期间的零写入当作正常积分回算。

发布前先构造完整`DepthLinearTiming`，通过原执行凭据复核后，
预备配对元数据→发布速度元组→完成元数据交接。
电机读端仅接受与当前元组精确匹配的预备记录，避免新速度借旧制动依据。
构造新记录期间，旧有效授权仍使用自己的完整证据；不新增串口等待或电机线程。

晚到的新近距离观测仍立即收紧/撤销旧授权；更远的晚到值不提高限幅。
最终电机写入处仍重新核对实际时间，不能借计算期间的耗时越过截止点。

## CAP238数值对照及局限

采用前轮日志的距离2.5648m、原请求116RPM、目标速度证据0.7641m/s、
当前双轮16RPM，构造固定输入对照；旧模型停止参考1.43m，新试验1.2m。
这里的运动证据是日志数值，不是对录像重新推理，也不是新实车轨迹。

| 深度年龄 | 旧策略理论上限RPM | 新包络RPM | 新执行量化RPM |
| --- | ---: | ---: | ---: |
| 100ms | 116.00 | 104.26 | 104 |
| 179ms | 116.00 | 89.16 | 88 |
| 181ms | 48.26 | 88.76 | 88 |
| 210ms | 46.41 | 82.95 | 82 |
| 249ms | 43.80 | 74.88 | 74 |

这消除了该输入在180ms处的离散跳变，但不是始终保持116RPM；
从批准开始就采用可逐步收紧的速度预算。实际外轮动量过大时仍可能立即撤销。
更重要的是，相对运动模型不能保证目标突然停止时仍守住固定间距；
用户允许的过冲、真实制动能力、轮速反馈延迟仍需现场验证。

## 开启、回退与观察

默认启动配置`car_control_modular/config/reid_runtime.ini`的`[astra_depth]`：

```ini
relative_continuation_enable = true
continuation_overshoot_m = 0.20
```

将第一项设为`false`并重启即可回退到原模型。旧配置未写此项时默认关闭。
余量合法范围0～0.30m；即使调大，也不会低于现有倒车启动参考。

新日志：`depth_relative_continuation_cap`、`depth_relative_admission_limit`、
`depth_relative_admission_veto`；记录原目标运动、采样年龄、原B、模型停止参考、
实际批准速度及拒绝原因。普通`depth_forward_continuation`同时记录策略与证据来源。

下一次现场对照重点：有效运动证据覆盖率、180ms附近速度短降次数、
深度真的超过250ms的次数、实际轮速连续性，以及目标突然站定后的最低距离。
不能将指令上限提高当作已经证明实车跟随改善。
