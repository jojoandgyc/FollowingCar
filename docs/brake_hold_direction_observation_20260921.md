针对 `run_20260921_134517_12929_aaba7c57` 的 CAP651～673。

## 修改边界

原来 NORMAL 停车等待提前返回，方向历史停在 CAP651 的右侧。
现在停车与可信观测分离：

1. 等待期间继续检查本帧正式轨迹与身份元数据。只记录当前活动 UID、
   新鲜且唯一的正式绑定，使用原始 YOLO 框和该观测的转角元数据。
   质量、几何、竞争或排除检查失败，以及 UID0、预测框、重复/过期观测，均不能更新。
   不要求画面只有一个人，不新增 ReID 距离阈值。
2. 只更新方向历史与最后可信横坐标，不测距、不写身份模板、不计算 PID，
   不发布动作、不延长任何电机授权。旧横向 PID 与保持动作在进入等待时清除。
3. 原执行器确认停稳后，若等待期间确有同 UID 新可信观测，清除旧冻结搜索方向、
   候选方向缓存和旧横向状态。当前正常控制帧重新决策；目标已消失则按更新后的
   方向历史进入原有丢失确认/搜索，不恢复旧动作。
4. 没有可信新观测或 UID 已改变时，不用未确认候选解除方向冻结。

停车条件、优先级、轮速反馈要求、纵向控制、RPM、ReID 和深度期限均未改变。
无新增串口读取、线程或固定等待时间。

## 日志

- `search_reacquire_brake_wait`：当前处理 CAP、最新可信观测 CAP、停车请求依据 CAP，
  以及 `observation_reason`。例如处理 CAP666、最新观测666、停车依据654是正常情况。
- `search_reacquire_brake_resume`：记录是否要求重判方向；`motion_authorized=False`
  表示该重置操作本身不授权运动。
- `control_direction_provenance`：区分处理帧、方向历史最新观测、决策显式依据。
  `action_evidence_capture_frame_id=None` 表示决策没有提供显式依据编号，不能当成当前帧。
  等待前的旧 PID 结果已清除，不再冒充等待后的新 PID 输出。
