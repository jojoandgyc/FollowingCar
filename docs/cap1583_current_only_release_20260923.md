# CAP1583：驻车到期只清电流，不追加速度指令

## 范围

针对 `run_20260923_170610_28930_44fd5b39` 中 NORMAL 后约 558ms 的
`PARK_RELEASE_ZERO`。原流程把“驻车电流清到 0A”和“再写一次双轮 0RPM”
绑定，额外改变了最后一次电机控制写入。本轮只解除这项绑定，不调视觉 P、
转向上限或停车时长，不操作硬件。

## 新流程

1. 普通原地驻车或搜索接回驻车执行原有 5A NORMAL。
2. 从 NORMAL 实际完成起保持至少 500ms。
3. 执行 `release_parking_current_only()`：清左右轮驻车电流至 0A，
   分别读回确认。成功路径不写速度，不追加 NORMAL/EMERGENCY/FREE。
4. 记录 `ordinary_park_current_released ... zero_rpm=False speed_write=False`。
   清电流完成时间成为新停稳证据的边界；软件停车锁不因此解除。
5. 旧 `forward(0)`、周期性零速不能覆盖停车。后端也保留零速写入抑制，
   防止旧调用路径再补零。新的有效运动指令通过原有 UID、时效、深度、
   停稳/图像及换向保护后才进入速度执行；后端非零写入解除该零速抑制。
6. 下一次真实驻车仍恢复 5A。普通周期驻车刷新不能重新开始 5A 保持。

`prepare_speed_mode()` 与新的 current-only 接口共用电流清零/读回实现，
但 current-only 不把运动置为已授权，也不声称驱动器已经切到某种速度闭环。
`normal_zero_hold` 仅是软件对后续零速写入的抑制标记，不是物理停稳证明。

## 未改变的边界

- 正常运行中的零速过渡、NORMAL 前已有的前置零速没有全局删除。
- 500ms、清电流后的新反馈/新图像要求均不变。
- 真正危险、显式停止、退出、I/O 失败与停车所有权变化的保护不变。
- 清电流后 2 秒仍无合格停稳证据时，既有故障急停和运动锁存仍保留。
  本轮不将“删除驻车后追加 0RPM”扩大为取消该保护；若仍触发，需要单独核对
  STOP 的物理响应，不能依据软件发送成功宣布车已停稳。

## 无硬件验证

新增 `tests/motor/test_cap1583_current_only_release.py` 共 7 项，逐项检查
双轮电流写入和读回顺序、无速度/STOP 追加、旧零速不覆盖、停车资格不等于
运动授权、新运动接续及再次 5A 驻车。更新原来期待到期零速包的旧断言，
将“零速写入时中断”测试改为“电流读回时中断”，保留异常和危险抢占覆盖。

与有界驻车、故障 STOP 顺序、电流生命周期、500ms 最短保持测试合计
75 项通过。实际晃动是否减少仍需新的安全实测，离线测试不替代物理验证。
