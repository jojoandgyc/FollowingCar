# 短暂测量空档：估计与恢复进度分离

## 本轮范围

基线：`run_20260916_203354_24874_a888c8d7`，移动CAP192~546，静止CAP546~615。
仅修复无观测导致的前馈全量重置、物理采样连续却按旧授权处理时刻重启恢复、停车统计遗漏。
不修改250ms ROI准入、180ms物理Depth期限、200RPM总上限、PID/前馈增益、ReID、搜索与近距离停车。
无实车动作。本轮也不承诺把新鲜Depth更新从约14Hz提升为30Hz。

## 1. 无观测不等于反证

明确旧框过期或可追溯的重复/旧样本，必须没有新raw/sample时间戳；同UID持续跟随，
无危险、无近距离警报、无停车锁存、编码器可信且<=150ms、两轮前进归一0~100RPM，
方位<=10度、yaw<=15度，旧证据仍在原180ms有效期，才保留供下一张新Depth使用。
没有向PID提供sample_timestamp，不新增授权，不更新旧证据时钟。
低yaw<=5时保留微分链；5~15度/秒没有新的配准深度/位姿对，仍清微分链，只保留
固定期限的前馈参考。日志单独统计 `derivative_reset=True`，不能靠改日志名字宣称估计改善。
过期、危险、换UID、背景/像素/跳变拒绝、反转轮速及更大转动仍走原拒绝路径。

## 2. 恢复以新Depth和实测轮速为准

旧租约过期仍立即撤销前进；保存<=350ms恢复参考不是运动权限，此期限沿用已有实现。
在已有实测恢复检查（新Depth<=180ms、同UID、无危险、距离变化-3~+30cm、
新鲜编码器及两轮0~100RPM）之上，只有：

- 原恢复参考不是已经降级的初次启动；
- 新旧物理深度采样间隔<=180ms；
- 新处理时刻距旧样本<=350ms；
- 实测基速至少是之前批准基速的90%，且之前批准>0；

才延续原恢复斜坡起点或已完成状态。参考一次消耗，不重复续期。
长物理断档、已明显减速或已经停车，不跳过原恢复；可用已有实测轮速抬升恢复下限，
但不恢复未经批准的旧PID请求。因此不是保证23次恢复全部消失，更不应删掉安全恢复。

## 3. 日志与统计

- `longitudinal_motion_observation_skipped`：原因、原采样时刻、剩余时间、是否仍清微分链。
- `depth_recovery_continuity_restored`：物理间隙/处理间隙、实测与原批准RPM、原斜坡起点。
- `depth_speed_recovery_limit`：显式requested/approved/lost RPM，避免200RPM比例的单位误解。
- `follow_metrics.py` schema=2把 `LZ30EMA 停车命令` 作为零轮速写入，含窗口前继承状态。
  清队列、停止意图不当作已执行停车。该命令日志在驱动stop_all后输出，仍不是车身停止时刻。
- 限幅损失按UID+物理样本去重，取该样本最大限制差；不是损失行程或时间加权速度损失。
  旧日志只有在启动明确输出forward_max_rpm时才转换百分数，否则未知。

旧静止段零指令比例应为61.25%，不是原脚本的1.75%；旧移动段仍16.42%。
新旧比较应以同一schema=2脚本重新统计，不能混用旧报表口径。
