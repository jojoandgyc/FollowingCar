# 小人体框的跟随资格（2026-09-16）

CAP822/825/833/834 的原始框约 38–42 × 49–57 像素，原先身份门槛
仅 16 × 28、面积 900。CAP825 通过晚到两帧观察取得 UID1；CAP834 本帧
输出 UID0，但处理完成前快环仍使用 CAP833 的目标。不能按日志中的
decision_capture_frame_id 单独推断身份确认来自哪张图。

正常和 rotation-only 配置的 `[identity_bank]` 共用以下资格门槛：

```ini
min_width_px = 32
min_height_px = 80
min_area = 3072
```

三项都必须满足（等于边界允许）。单位是原始 RGB 检测坐标的像素/像素²，
当前为 640×480，不是网络输入尺寸，也不是 DeepSORT 扩展框尺寸。
如改变 RGB 分辨率，必须同步重评这些像素门槛。模块默认值保持兼容；
运行入口由配置加载到现有 `Y8_IDENTITY_MIN_*` 环境变量。

`RKNNVisionPipeline._record_detector_output` 在正式框送入 ReID/DeepSORT、
低分框参与聚类/竞争/搜索观察之前筛除小框。原始检测和低分原始检测仍
保留用于录像与诊断；`last_follow_size_rejections` 每帧重置。日志事件
`follow_bbox_size_rejected` 记录 CAP、formal/probe 来源、原框坐标、宽高、
面积、分数及拒绝条件。直接 tracker 路径的质量分层也使用原始检测框。

小框不产生新的身份/位置/方向或纵向授权。原目标消失后的既有短时保持、
授权过期停车及搜索机制不变；本次不清空活动 UID、不调 PID/速度/ReID阈值。
这项限制主动放弃过小的真实远处目标，不能宣称所有被过滤的框都是误检。
