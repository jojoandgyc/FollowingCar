# CAP382：350ms 执行响应补偿试验

## 开关与回退

`car_control_modular/config/reid_runtime.ini`，`[steering_pid]`：

```ini
execution_response_trial_sec = 0.35
```

效果变差时改为 `0`，停止当前运行并重新启动程序，恢复试验前的预测、前进反打保护口径及共同加速交接。
这是单一试验开关，不回滚仓库、不覆盖其他改动；模块默认值为 0，生产 INI 显式开启。
若启动环境单独覆盖 `VISIBLE_STEERING_PID_EXECUTION_RESPONSE_TRIAL_SEC`，也应核对/取消该覆盖。

## 时间模型

依据 `run_20260923_170610_28930_44fd5b39`：轮差归零写入完成于 18491.709692，
实测轮差约 1RPM 的反馈时间为 18492.053759，约 344ms。
这只是一次复合减速响应，不证明启动、换向和停车都有固定 350ms 纯延迟。

试验预测预算为“图像年龄 + 原有下发响应预算（限定 0～100ms）+ 350ms 执行响应”。
350ms 替换旧的执行/减速部分：不再额外叠加原来的视觉响应窗口、反打脉冲时间或
角速度平方除减速度项。视觉位移估计和编码器位移估计仍取更保守的减速结果，不相加。
既有下发预算是配置估计，不宣称已经测得每条命令的实时排队时间。
不添加 sleep、不排队重放未来指令、不延长深度/视觉授权。

## 撤销转向后的交接

新增 `TurnResponseTrial` 保存同 UID 最近响应窗口内实际写入成功的双轮目标。
记录的是最终执行量，不是 PID 请求；UID 变化清空历史。

检测到转向减小、撤销或反打时，限制共同前进速度不高于最近实际下发的基速，
有可信反馈时还不高于当时实测平均轮速，避免 CAP380 的 19/39 → 63/77 突然共同加速。
新深度的更低上限、停车和授权撤销立即生效；历史不产生运动权限。
至少经过响应窗口，且两个独立新鲜反馈确认实际轮差已匹配较小请求/接近零后，才释放该限制。
重复反馈、周期零轮差不能提前释放或不断重置起点。这里限制的是共同加速，不是强制转满 350ms。

## 前进反打与原地反打分开

试验开启后，主循环和快环可以保留有合格预测制动证据的反向轮差，不再无条件
按 `target_still_outside_center` 清掉。普通错误方向输出仍受保护。

最终写入必须同时满足当前同 UID 可信视觉、采集年龄不超过 250ms、目标正在接近中心、
新鲜同向一致原始/滤波角速度、双轮实际非负、残余轮差与制动方向相反、有效前进授权。
允许最多单轮修正 6RPM，并限制不大于前进基速，因此不会让任一车轮反转。
制动连续输出窗口为 80ms，后续新帧不能延长同一制动段；到期撤掉反向轮差并继续限制共同加速。
80ms 是软件检查期限，真实撤销时刻仍受控制周期和 I/O 耗时影响，不是硬实时保证。

写入前再次核对反馈、授权、意图和窗口，反馈读取后授权到期也不得继续执行反打。
前进失权不能将旧前进制动意图转为原地反转脉冲。没有合格反打证据时仍可撤销轮差、
限制共同加速，但不伪造运动权限。不把普通差速前进一律转换为 NORMAL 驻车。

500ms 驻车、电流生命周期、真实车轮反转保护、正常 20RPM 差速上限及停车后 4RPM 找正保持不变。
