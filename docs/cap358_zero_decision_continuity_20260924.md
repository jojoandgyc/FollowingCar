# CAP358–405：零速决策与交接修复

依据：`run_request_0428_modular_logs/run_20260924_203112_41725_ca2967e7`。
本次修改代码并做无硬件回归，未启动小车、串口或摄像头。

## 目标与边界

减少“普通限幅／取消旧队列／预测证据暂缺”被当成整车停车的情况。
不提高 RPM、P、ReID 阈值或深度授权期限，不缓存重放旧电机指令。
明确失权、危险、身份不确定且无有限横向资格、真正轮子反转仍保护。
不是删除所有零指令，也不是用定时持续运动掩盖授权中断。

## 修改

### 1. 编码器预测制动不再一律等同于立即清零

正常前进期间，目标仍明显偏轴，可信编码器显示同向转动，但缺少可用的
相对画面回中证据时，可有一次最长 150ms 的同向减速核验：

- 请求不超过实测半轮差的 25%，且单轮不超过 2RPM、原位置请求上限。
- 新鲜远偏轴图像可启动；较旧图像仅能使用先前真正验证过、仍在有界寿命内的外移历史。
- 重复帧、新的未知运动帧及 PID reset 不能重启已使用预算。
- 可靠回中、进入中心、高角速、证据过期继续优先制动；原地转向与倒车不新增权限。
- 不生成新身份、不刷新电机授权、不增加前进量，也不允许执行层再增强这个减速请求。
- 快环平滑不能把 2RPM 的减速上限抬回旧的较大差速。

日志输入单分支对照：CAP361 在已有验证外移历史时 0→−1RPM；CAP378 为 0→−2RPM。
这是受限减速接续，不是恢复满差速；这些对照不能证明真实轨迹结果。

### 2. 普通限幅和差速增强使用不同的证据范围

`action_runtime` 在辅助调用前后记录真实改变，普通 −10→−7RPM 模式限幅
不再误套增强分支的 250ms 采集、100ms 编码器窗口。
真正增强仍在最终安全检查之后再次核验；安全零指令不能被增强资格拒绝。
最终 UID、轴授权、危险与反馈检查仍适用于所有非零指令。

### 3. 取消旧动作队列，不等于撤销新横向授权

只对 `target_visible_low_quality_yaw` 的同 UID 交接：

1. 主程序先作废旧动作版本，正常清理旧队列。
2. 发布当前帧新的有限横向意图。
3. 确认周期执行器可接管、当前帧匹配、无前进授权、横向仍有效后，不设置全局停车标志。
4. 发布或验证失败，仍恢复原停车处理；不清除已有或后来到达的真实停车标志。

同 UID 的新鲜原地转向更新，也能使用已有的一次即时重算，不必先插入零速。
重算后仍经过全部换向保护；连续变化只能重算一次，不能无限重试。

### 4. 对齐有限横向的减速交接接口

当前明确合格的有限横向意图也可使用已有的“内轮已停、外轮仍在减速”条件：
实际写零后，两个独立新反馈确认，才允许有界零均值转向。
只有状态标签低质量、没有有效有限横向意图时不能使用这个入口。
CAP376–378 那类内轮仍明显向前的反馈仍不能直接反转。

### 5. 避免无效裁切触发停车补看

当前帧唯一候选同时满足：身份仍未确认、明确 `secondary_evidence_unavailable`、
全身和躯干可比模板均为零、侧边裁切且在画面外侧 15%，才暂缓检测层的停车补看。
继续已有搜索方向，不赋 UID、不恢复前进、不消耗尚未使用的补看机会。
覆盖改善后仍能正常补看。中央模糊候选、缺元数据或存在竞争时保留原处理。
重复、乱序图像不推进观察／缺失计数，也不重开等待期限。
结束检测层观察不等于身份确认，不解除独立安全制动。

本轮真实日志只读判据对照：CAP393/394/396/397/398/400 暂缓；CAP418/420 不暂缓。
