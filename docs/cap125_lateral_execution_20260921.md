## 1. 撤销已经不适用的过零等待

原链路：正向运动 → 深度授权暂时退出 → 请求原地左转 → 进入左轮过零等待 →
深度恢复、请求改为双轮正向 → `same_yaw_cross` 保留旧等待，最终仍写入双轮零速。

现在仅在以下条件同时满足时，允许新的当前请求接管：

- 调用方开启正常可见跟随的前进交接，并批准当前前进授权；
- 待处理的是混合正负号的旧原地转向，不是双轮倒退；
- 新请求两轮非负，至少一轮为正；
- 反馈可信、新鲜，且采样时间晚于该过零等待的起点；
- 当前请求没有与反馈或尚未被反馈覆盖的旧下发方向发生反转冲突。

使用 `cross_obsolete_turn_forward_handoff` 标记。直接采用本次已限幅请求，
不重放旧轮速，也不另加 5RPM 起步斜坡。
真反转、双轮倒退历史、无效反馈、搜索/未授权入口仍保留过零确认。
实际写入前的 UID、横向版本、纵向授权检查不变。

## 2. 分开策略上限和瞬时上限

`VisualSteeringPidResult.correction_policy_limit_rpm` 保存配置与调用方明确给出的上限。
原 `correction_limit_rpm` 仍表示本次计算经过小误差、制动等处理后的瞬时上限。

正常、可信、前进跟随的视觉意图传递策略上限，快环继续用新鲜反馈重新计算动态限幅。
例如当前制动上限5RPM、策略上限10RPM：

- 仍有反向残余角速度：继续受5RPM限制；
- 残余角速度消失、目标仍明显偏离中心：重新按既有策略计算，允许恢复到10RPM范围；
- 接近中心或触发预测制动：仍减速/清零；
- 显式调用方限幅、低质量、原地转向和后退路径：保留原约束。

没有提高10RPM配置，也没有取消启动3RPM/100ms、目标角速度匹配和中心停车策略。
先排除执行中断与临时限幅被持续沿用，再依据实测响应评价这些参数。

## 3. 诊断字段

复用现有日志及编码器缓存，不增加串口读取、线程或反馈等待。

- `visible_wheel_dispatch`：增加 `requested_diff_rpm`、`applied_diff_rpm`、
  `feedback_diff_rpm`，符号均为前进归一后的左轮减右轮，负值代表左转；
  增加反馈可信状态/年龄、上一轮速对及下发时间、本次下发时间、来源CAP。
- `feedback_after_previous_send_ms`：反馈采样相对上次下发的时间，可以为负；
  不能将本次写入之前采到的轮速当作本次指令的响应。
- `lateral_intent_tick`：增加策略上限、瞬时限幅原因、剩余有效时间。
- `lateral_intent_expired`：增加来源CAP、原图年龄及逾期时间。
