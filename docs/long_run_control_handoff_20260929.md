# 长时间测试后的接续与诊断修复

基线：`run_request_0428_modular_logs/run_20260929_200957_54494_c3d555cc`。
本轮只修改软件并做无硬件回归，不启动跟随程序，不打开电机串口，不改 RPM、身份阈值或安全期限。

## 本轮修改

1. **Depth30 两阶段测距。** 原路径在共享控制锁内进行像素统计、距离过滤和控制计算。
   新路径在锁内复制测距状态，锁外对私有副本计算，再在锁内复核并提交。
   主视觉更新、目标切换、搜索、停车保护、退出或样本失效均不能被旧计算覆盖。
   活跃测距状态修订号改变后，旧事务丢弃；被丢弃的事务不写滤波历史或正常测距诊断。
   新测量仍使用真实物理时间，不把完成时间当成采集时间，不延长授权。
   旧授权自然到期不等同于新测量失去资格；实际停车后的恢复保护仍由原执行链负责。
2. **搜索方向只接受当前正式身份。** 原始轨迹存在、历史 UID 映射和强 ReID 相似度
   均不能替代当前帧 UID 确认。CAP2284 式 `UID0 + mapped_uid=1` 不再翻转可信搜索方向。
   候选仍可观察、停车补看；观察不授予身份、前进或模板更新权限。
3. **匹配首次开销前置。** 在视觉流水线准备阶段预热可选匹配后端。
   有限数值的单行/单列代价矩阵直接求等价最小值；其他输入保留原求解/回退行为。
   不更改匹配阈值、马氏距离或身份判断。
4. **限速原因分层记录。** 保留旧 `demand_limit_reason`，新增 `final_limit_reason`、
   `pre_settling_cap_rpm`、`execution_anchor_rpm`、`execution_ramp_dt_ms`、
   `ramp_output_rpm`、`brake_recovery_cap_rpm`、`pre_quantization_rpm`。
   CAP5240 式“制动允许约79RPM、恢复起点约30RPM、最终请求30RPM”能明确显示
   `execution_recovery`，不再只能看到制动包络。`limit_scope=pi_request` 明确这还不是电机实测速度。
   本项仅改诊断，1000组固定种子的离线输入前后，输出和控制状态摘要一致。

## 保留的边界

- 新 PI 更新的物理样本年龄仍受原180ms上限约束；250ms只是原有受限延续上限。
- 已合法固定关联的 bounded-history 样本沿用原有一次完成规则，不能拿该证明启动下一次旧框测量。
- 停车/零指令、身份冲突、危险、过期和退出保护均保留；不靠跨越真实撤权来抹掉降速。
- 旁路独立深度仍未接入电机授权。
- 未全局放宽侧边裁切身份规则，也未调整制动能力假设。这两项需正确/错误人物对照以及实际停车响应证据。

## 复测重点

下次运行原命令，比较 `control_lock_stage` 的 `lock_hold_ms` 与
`depth_compute_outside_lock_ms`，不把锁外计算误算为持锁耗时。
观察 `depth30_prepared_discard` 的原因，区分正常旧事务取消与持续计算饥饿。
比较 `expired_waiting_control_lock` 次数、可信新深度批准间隙和最终轮速短降，
并用新增限速来源区分制动、恢复和软件斜坡。
不能用离线单元测试宣称实车卡顿已消失或达到某个性能改善比例。
