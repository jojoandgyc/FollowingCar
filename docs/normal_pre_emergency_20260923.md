# NORMAL 前置 EMERGENCY 试验

针对 CAP416 后持续摆动，按要求只调整停车入口，不修改 PID、RPM、
反打力度或驻车时间；本次仅做无硬件验证。

运行时 `MssdMotorBackend.send_stop(mode="normal")` 的顺序：

1. 保留既有双轮 0RPM 清除及配置中的清零延时。
2. 对双轮执行一次 EMERGENCY，等待驱动通信调用成功返回。
3. 按既有逻辑恢复、读回确认 5A 驻车电流（已确认的缓存值可复用）。
4. 双轮执行 NORMAL；上层从这次调用完成后开始计算既有 500ms 驻车期。

两条 STOP 之间不插入速度指令，不新增固定等待。发送成功不等于物理停稳。
日志 `normal_pre_emergency` 记录前置急停成功及耗时；既有 NORMAL 日志保留。

前置 EMERGENCY 失败时立即抛出异常，不继续设置电流或发送 NORMAL，
不标记驻车成功。电流设置失败时保留既有 EMERGENCY 兜底。
已驻车的 NORMAL 刷新不重复插入急停；EMERGENCY、FREE 和故障锁存入口不变。
启动驻车原本已有 EMERGENCY 前置步骤，不另加一次。

独立停车诊断脚本保留原测试序列，便于与此前试验比较，不自动随主程序改变。
若需回退，只撤销 `send_stop` 中新增的前置 EMERGENCY 及其日志，
并恢复相应命令序列测试预期；不回退其他已有控制修复。

实车仍需观察：前置急停完成到 NORMAL 完成的时间、停车后轮速/位置、
电流和车身是否持续往返摆动。这次改动尚不能证明摆动根因已解决。

无硬件验证结果：电机测试 738 passed；全量 4583 passed、3 failed。
3 项失败仍为既有目标距离断言（期望 1.5m，配置 1.4m）及两项搜索方向测试，
本轮未改动它们。单独的 NORMAL 映射离线检查通过，`git diff --check` 通过。
