# 同向轮速恢复与深度边界连续性

## 本轮范围

基线 `run_20260916_220119_31292_a0436efb`，移动CAP195~514，静止CAP514~606。
移动采集17.142秒，指令窗口尾随180ms。仅修复过零等待退出、2.5m附近重复确认，
并记录执行损失。不调PID、匹配80RPM/总200RPM、恢复25/45RPM、ReID、搜索或Depth180ms。

## 1. 过零等待可以在方向已正确时退出

过去等待状态要求原反向车轮连续两帧<=1RPM，即使后来已经正向，也持续等待。
本轮保留安静两帧的原路径，另增**仅正常双轮前进**的同向恢复：

- 两次不同且递增的反馈时间；反馈年龄<=150ms，两次反馈间隔<=150ms；
- 两轮反馈均可信、有限，且位于0至本轮请求RPM之间，不再存在反向证据；
- 同一请求方向；反向或无效反馈打断确认，重复反馈不计数；
- 通过后按当前请求轮速比例输出，最大轮先不超过5RPM，再按实际已下发轮速
  以最多80RPM/s恢复；两轮同比缩放保留曲率。一次调度最多补100ms，不因长时间
  调度空档突然跳至高转速。减速和显式零不等待爬升。

旋转或倒车仍走原静止确认。真实反向、无可靠反馈时超时继续零，不会超时强行放行。
下发前的深度期限、UID/状态和横向资格复核仍有效；恢复期间Depth失效立即撤销基速。
新增 `cross_aligned_resume`、`cross_resume_ramp`；每次执行日志补充双轮反馈、反馈时间、
pending方向、quiet与aligned计数，方便区分真实反转、测量尖峰和过严退出。

## 2. 2.484 -> 2.502m不应自动变成新表面

只在原保护阈值±0.10m附近开放一条连续路径（默认2.4~2.6m）：

- 已有同UID锚点；上一和当前观测都至少三个躯干区域一致；
- 原锚点年龄、新Depth年龄、物理采样间隔均<=180ms，且必须是新样本；
- 距离变化<=8cm且不超过原跳变上限，变化率<=1.5m/s且不超过原速度保护；
- 框面积、宽、高变化在±15%，中心X/Y变化不超过各画面尺寸的5%；
- 仍经过原像素、背景、躯干簇和身份绑定检查。

满足这些条件仅免去“跨过2.5m”引起的重复三次确认，按当前真实采样时间更新。
不伪造重定位确认凭证，不更新身份库。首次测距、旧锚点、单区域、几何突变、远处背景
以及真实距离跳变均不适用。新增 `depth_boundary_continuity` 日志，保留候选和锚点数值。
这是窄范围连续性修复，并非取消所有大框保护。

## 3. 执行指标不再停在PID批准层

`follow_metrics.py`新增：

- 正向请求最终下发双轮0的次数；
- 请求基速到实际下发基速的损失RPM分布（按执行记录，不是物理采样数）；
- 真实零轮速命令驻留时间，按相邻且轮速一致的执行日志归因；无法归因写unknown；
- 过零等待/超时零指令时间占比；边界连续路径的不同UID/采样数。

下发轮速仍不是实测轮速。应结合编码器和距离误差验证，不能只看tick的base_rpm。
旧日志也可算请求/下发差，本轮基线272条正向请求中17条下发0；平均损失2.515RPM。
移动段过零等待零指令共1.014秒，占指令窗口5.854%；全部零指令3.501秒、20.21%。
其中部分停车属于真实深度断档/异常，不应全部删除。
