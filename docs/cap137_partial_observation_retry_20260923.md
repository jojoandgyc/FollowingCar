## 修改

1. 搜索 probe 与正式轨迹使用同一质量字段契约：写入实际检测框、来源、质量布尔值及原因。使用真实 `_bbox_quality()` 结果，不能把弱框或三边截断框补成通过。
2. `retry_evidence_source()` 将原强全身证据与可靠近期躯干证据分别核验。partial 入口要求：当前 UID、近期可靠躯干为 match 且不超过 0.34、实际框质量通过、OSNet 躯干来源、当前帧/UID/候选编号对应的身份竞争通过；灰区、排除、明确几何或身份矛盾不能触发此入口。
3. 原追加停车状态机保持不变：每个搜索 epoch/UID 一次预算，两张不同采集时刻且位置/面积连续的候选才进入；当前最长 300ms。只请求零速，实际写零成功后的新图像（另有 80ms 间隔）才满足完成条件；超时、候选丢失/歧义按原规则结束，不续期。
4. 正式 raw track 1 到 probe -1 之间，停车观察依据同一候选的新鲜框和合格身份证据接续，不依赖 raw ID 相同。**不复制旧 raw track 的身份确认计数、UID、模板或可信方向锚点给 probe。** 身份接回仍独立判断，不能把两张局部连续图像直接当作同一身份。
5. 日志可区分 `unique_strong_observation` 与 `unique_partial_observation`。

这次未修改搜索方向、深度/前进授权、轮速上限、电机制动能力或模板学习门槛。追加停车是否真正改善图像，仍需实车对照；零速写入回执不等于物理停稳。
