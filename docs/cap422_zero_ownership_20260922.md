## 改动

### 1. 避免差速尚未建立就继续共同大幅加速

新增 follow_turn_acceleration_priority_enable，运行配置开启，可独立关闭回退。
仅作用于可见目标、已有新鲜前进授权的双轮正向加速：

- 请求轮差至少10RPM、实测同向轮差落后超过4RPM，才检查共同加速。
- 内侧轮暂限到新鲜实测值上方2RPM，外侧轮保留请求差值。
- 两轮目标都不得超过原批准值，也不得因此降至实测值以下：只减小加速要求，不新增制动。
- 原命令需要减速、轮差已建立、直行、原地旋转、反向或反馈无效时不采用此修正。
- 不给无深度授权的单轮前进，不抬高基速/轮差，不延长时间戳，不取消真正的反转保护。

CAP422的一个已知输入：请求56/40，实测16/15。
新函数输出33/17，仍为16RPM轮差；意图是内侧轮少加速，让轮差较早建立。
这是输入输出验证，不是新车速轨迹预测。它可能降低短时前进速度，需要实车比较。

### 2. 修复过零反馈比较基准

旧逻辑将反馈时间与最近一次重复零速写入比较。复现中，25ms写入周期、
40ms反馈延迟，即使连续低残余反馈，也可能永远无法累计两次确认。
改为本次连续零速第一次成功写入时间 zero_since；非零写入立即清除此基准。
重复、过期、停车前反馈仍不能重复确认；4/8RPM边界、两次新样本、危险检查不变。
此修复不代表CAP447–455的大负轮速可以放行，也不保证消除本段全部等待。

### 3. 明确记录清零责任

visible_wheel_dispatch 增加：

- zero_owner：requested_zero / forward_loss_handoff / wheel_zero_cross / none。
- forward_loss_input_rpm、wheel_guard_input_rpm：各层实际接收的轮速。
- turn_priority、common_accel_removed_rpm：共同加速是否被限制、减少多少。
- zero_since：连续零写入起点，与最近下发时间区分。

现有depth_linear_revoked继续记录撤销前进的上游原因。

## 下轮验证

同类“向右偏离且接近设定距离”的场景，优先看：

1. 双轮零指令占比：当前62.6%，试验争取低于30%，按上述来源拆分。
2. 最长连续零指令：本段至少897ms，争取低于400ms；高反向速度等真实危险单列。
3. 非零右转首次下发到实测同向轮差>=10RPM的时间；区分增速滞后与软件清零。
4. 原请求/执行轮差、共同加速限幅持续时间，防止长时间压住前进。
5. 最大偏离、丢失次数、距离误差和最近距离；不能仅降低零指令占比而增加过冲。

未调整ReID、深度门槛、1.4m设定、250ms授权、30RPM轮差上限或5A/100ms驻车。
未操作实车。若仍出现较大双轮负反馈，下一步需要验证执行层实际停车响应，
不能靠超时直接批准高转速反转。
