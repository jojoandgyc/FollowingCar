# 录像吞吐与真实时间回放

本轮只修改录像路径，不修改电机、身份确认、深度授权或控制参数。

- 后台使用 OpenCV JPEG quality=90 编码，再由 FFmpeg packet-copy 封装 AVI；不进行二次编码。启动不可用时回退原 OpenCV writer。
- 绘字使用 LINE_8，保留轮速、目标速度及深度 ROI 数值等诊断信息。
- 队列仍为 60；满队列提前拒绝，避免无效 RGB 拷贝。不阻塞采集等待录像，不修改全局 OpenCV 线程数。
- VIDEO 是保存序号，CAP 是采集序号，不能人为合并。新增 T+ 为相对首张保存帧的真实采集时间。
- CSV 新增 recording_* 分项耗时、队列年龄、CAP 缺口和累计丢帧；日志每 5 秒及结束时输出最近 120 帧各项平均/P95/最大耗时。

640×480 同帧离线测试：绘制中位数约 9.93→3.31ms，编码写入约 11.84→2.29ms。不是实车并发负载结果，后台仍会共享 CPU、内存和磁盘，不能保证零影响或零丢帧。

运行命令不变。回退编码后端：

```bash
FOLLOW_VIDEO_FAST_MJPEG=0 ./run_request_0428_modular.sh
```

## 按真实时间回放（停车、结束运行后执行）

原 AVI 为固定帧率，有丢帧时播放会加速。离线工具按对应 CSV 的采集时间生成可变帧率 MKV，不覆盖原录像，不补造丢失画面，不自动在小车运行期间执行：

```bash
python3 tools/retime_recording.py run_request_0428_modular_logs/<本轮目录>/camera_raw.avi
```

输出同目录 camera_raw.realtime.mkv。缺失期间保持上一张真实画面；末帧之后无额外时间推断。工具只复制 MJPEG 包，临时逐帧 AVI 用于兼容板载 FFmpeg 的毫秒时间基；需要额外临时磁盘空间。必须使用本轮配套 CSV。
