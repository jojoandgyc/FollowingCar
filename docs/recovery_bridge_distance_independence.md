## 1. 恢复资格使用同一反馈范围

CAP188 新鲜深度 2.539m、实测左右轮 99/103RPM、请求 84RPM，却因旧 `<=100`
门槛重启恢复，批准 24RPM。并非轮子真的不转，也不是 PID 只请求 24RPM。

三个恢复入口统一读取现有估计器 `max_abs_ego_rpm`。当前 profile 配置由
80RPM 匹配预算＋约44.074RPM 距差预算＋5RPM 容差得到 **129.074RPM**，
不是把异常轮速截成合法值，不是增加指令预算；legacy 配置沿用其估计器边界。
非有限数、负轮速、不可信/过期反馈、危险、近距离或不连续深度仍走原保护。
正常恢复的实测轮速包络、50ms 加速步长不变。

无硬件同输入对照：旧逻辑 84→24RPM；修后 84→84RPM。
反馈超界仍拒绝。诊断日志补充 left/right RPM 和实际 feedback_limit_rpm。

## 2. 桥接只约束旧前馈，不封住新测距

原先 controller 把整个请求截到上一批准速度，runtime 又做一次相同截断。
新 profile 中：

1. 桥接的人速贡献继续随原始时间衰减，不能增长或续期；距差输出可以由新鲜可信
   Depth 单独更新，仍经过当前制动包络、正常加速与实际恢复限幅。
2. runtime 只有同一物理样本的 profile 结果、同 UID 且原前进授权仍有效时，才可合并。
   如果原授权进一步减小，扣掉不能保留的旧前馈部分；同次独立纯距离结果可继续使用。
3. 人速先验到期，撤去先验，不撤销尚新鲜的独立距离结果。纯距离缓存经过同次计算的
   制动/加速/输出上限；不再被旧普通距离上限或微小前馈预算二次压低。
4. 没有旧有效前进授权时，仍必须经过原 `fresh_distance_recovery_percent`：
   新鲜可信远距、同 UID、实测轮速和单步恢复检查。旧先验不能恢复旧授权。
   危险、显式停止、倒车、搜索、制动保持、身份改变不能被该路径绕开。
5. 同/旧物理样本不重算、不重授；180ms 截止和电机写入前复检保持。
   legacy PID 的桥接整速限制不变。新鲜人速证据到达后才允许重建更高匹配基速。

CAP193 无硬件对照：24RPM 旧批准、24RPM 桥接基速，88.5ms 后新深度有效。
旧输出仍为24；修后按240RPM/s斜率得到45RPM，runtime 量化批准44RPM，
不是直接跳到约68RPM 未限斜率请求。后续新深度可继续有界提速，旧基速不能借机回升。

新增 `depth_bridge_components` 记录旧批准、旧前馈、独立距离预算与合并上限；
`longitudinal_motion_bridge` 增加 `cap_scope=prior_only`，其原
`acceleration_allowed=False` 指旧先验自身不能提速，新增字段区分新距离提速资格。
