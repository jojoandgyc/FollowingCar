旧策略到 1.80m 才启动；旧横向纯旋转覆盖新前进；居中还插入了 119ms 零速。

## 单一距离设置

主配置 `[distance] target_distance_m` 仍是用户唯一需要设置的跟随距离。
`auto_tune_follow_distance=true` 时，派生值为：

| 参数 | 自动规则 | 目标 1.50m 示例 |
| --- | --- | --- |
| 静止启动追赶 | 目标 + 0.08m | 1.58m |
| 静止停止回差 | 目标 + 0.03m | 1.53m |
| 静止近距离只旋转 | 不超过目标 + 0.03m | 1.53m |
| PID 死区 | 0.03m | ±3cm |

这些是控制阈值，不是已经实测证明的距离精度。关闭自动模式可保留显式参数。

## 两个轴、同一个纵向授权

RGB 对齐 Depth 与最新 Depth30 使用同一距离安全判定，按物理深度时间戳去重。
有效纵向状态包含方向、受限百分比、UID、物理时间戳。
横向零输出只清轮差；横向非零输出与当前有效纵向速度合成，不按旧帧模式覆盖前进。
没有有效纵向授权时，仍禁止凭视觉/旧框恢复前进。
旧、重复、保持样本不能续 180ms 授权；较旧正向样本不能覆盖较新的停止。
Depth 批准的 DRIVE 和 STEER 使用一致的 RPM 映射，不再重新套 40% 启动下限。
新的纵向决策会撤销旧动作版本；前进及差速包在电机写入锁内再次核对版本，
避免已经排队的旧速度在新的减速或零速之后补发。

## 受限速度前馈

仅同 UID 的连续新鲜、已关联原始深度样本与可信编码器轮速参与估计：
目标沿相机前方速度约等于距离变化率加车体前进速度。
原始物理样本用于速度计算；滤波距离仍用于距离误差。不能用滞后的中位数配原始时间戳。
仅正前方约 ±10°、角速度不超过约 5°/s 使用；跳变、失效、竞争/低质量目标不得授权。

匹配基速**替代** PID 的起步基速，不重复相加。默认最大匹配基速为 40RPM，
其中超过原 20RPM 基准的附加补偿最多 20RPM；有效时近端 Depth 上限可随匹配基速提高，
但仍不超过已有远端/全局上限。没有此证据时保留普通近端限速。
目标距离附近仍在同向行走时允许持续匹配；低于目标约 3cm、证据失效时退出匹配。
普通距离控制、安全降速、障碍物停车和既有倒车策略仍独立约束最终动作。

轮周长沿用现有 `encoder_wheel_circumference_m` 暂定值 0.60m，实车标定误差、滑移、
曝光、深度采样错误和机械惯性都会影响结果。离线仿真不能替代实车验收。

### 限量深度诊断

标准启动脚本已提供 `FOLLOW_LOG_DIR`，因此默认在本轮目录下新建
`depth_diagnostics/`；直接启动 Python 且无此环境变量时不写快照。
用 `FOLLOW_DEPTH_DIAGNOSTICS_ENABLE=0 ./run_request_0428_modular.sh` 可单独关闭。

- `observations.jsonl`：逐次目标测距的 CAP、物理样本/观测时间、候选值、接受 raw、
  滤波或保持值、各 ROI 边界/有效像素/最低要求/深度簇/空间支持率和拒绝原因。
  每区最多列 8 个簇，超出数量另记；上层最终 used 距离仍查主日志 Depth timeline。
- 每区 `nonzero_below_0_4m` 只是原始非零近点数量，不是可信障碍物或停车授权。
- 新物理观测被拒绝时触发快照，间隔至少 2s，最多 24 组；每组最多 3 张前序/被测
  Depth 和 2 张后续 Depth。8 帧环形缓存之外的历史样本无法补存。
- `.npz` 中 `depth_mm` 为原始 uint16 毫米图（保留 0 等无效码）；`rgb_bgr` 为
  最大边不超过 640 的 RGB 相机 BGR 抽样预览；`metadata_json` 记录各自时间戳与 CAP。
  RGB 仅作最近时刻配对，超过 200ms 就记缺失，不声称硬件同步或空间已完全标定。
- 后台写盘、队列最多 8 条、总写入上限 256MiB；满队列丢记录并计 dropped；磁盘
  错误禁用诊断，不影响测距决策。已有同名诊断目录不会被覆盖。

读取示例：`np.load(path, allow_pickle=False)["depth_mm"]`。快照不进入 ReID、PID
或安全控制。尚未新增基于全图 0.4m 深度的紧急停车策略。

离线回归覆盖真实视觉入口、左右/零轮差合成、旧样本与到期、UID/质量拒绝、
已复制 ROI 撤销、串口锁前准备动作的保留/撤销，以及诊断慢盘、容量和错误隔离。
实车验收重点比较模式切换急停次数、连续前进时长与编码器实际轮速，不只看 PID 输出。

## 可见跟随的轮速连续执行（2026-09-16）

针对 CAP1398～1562 的 STEER/TURN 频繁切换，执行层增加受限连续路径：

- 仅用于 Depth 纵向仲裁已开启、UID 存在、目标可靠可见、非搜索、非旋转脉冲的
  正常 raw RPM 跟随；搜索、低质量目标、倒车、急停和 shutdown 不使用此豁免。
- 不再仅因 FORWARD/STEER/TURN 动作名称变化调用模式切换急停或额外减速循环。
  差速按 `left_forward = base + yaw`、`right_forward = base - yaw` 表达，低基速时
  允许内轮目标为负数，但必须经过下述实际换向检查。硬件左右电机符号保持不变。
- 电机锁内重新检查 UID、横向动作版本和原始 Depth 授权；过期只撤销基速，
  横向失效只撤销轮差，不刷新原授权时间，不用旧动作恢复纵向速度。
- 编码器必须可信且不超过 150ms；反馈不可用时输出零。若某轮实际仍沿目标的
  反方向运动（超过 1 RPM），先输出双轮零速，避免单轮清零引入额外位移。
  连续两条不同时间戳的反馈确认待换向车轮绝对轮速不超过 1 RPM，才允许当前
  动作继续。超过 250ms 仍未停稳时记录 timeout 并保持零，不盲目放行。
- 不在执行线程里 sleep 等待换向；前进类动作等待时，新反馈可触发有下发间隔
  限制的重试，无需等待常规 0.5s 保活。只重算当前动作，不缓存重放历史轮速。

新增日志 `visible_wheel_dispatch` 包含 UID、base/yaw、请求及下发的归一化轮速、
Depth 是否有效和原因：`continuous`、`explicit_zero`、`cross_wait_zero`、
`cross_timeout_zero`、`feedback_unavailable`。`visible_wheel_revoked` 表示写入前资格
已改变，旧数据包未下发。这里的 applied 是命令，不是编码器实测速度。

本轮不修改搜索、ReID、PID、RPM 或 60% 总前进上限，也未操作实车。
新增 fake-driver/纯逻辑测试覆盖符号映射、连续差速、真实换向、反馈重复/过期/异常、
Depth 与横向分别撤销、模式隔离、状态竞争和换向后的及时恢复。
下一轮需同时比较模式切换急停次数、换向清零时长、连续实测前进速度和距离误差；
不能把急停日志减少直接视为距离保持已经改善。反馈不足或真实换向仍会停车。

## CAP695～834：最新深度优先与下发预算（2026-09-16）

本轮日志已无动作名称切换急停，但双轮零速指令仍占对应执行时段约 32%。
CAP834 的历史对齐样本在批准 55% 前进时仅剩 4.4ms；动作出队已花 8.6ms，
最终因物理深度过期写入 0/0。仅增加线程唤醒或提高 PID 不能解决这个时序。

本次局部修复：

- 正常视觉路径在同 UID 持续可见、上次选中目标一致、唯一可靠检测框来源、
  无搜索/重捕获/低质量/停车状态且真实 RGB 年龄不超过 180ms 时，优先读取 latest
  Depth。复用现有空间关联、多区域一致性、跳变和物理样本去重，不先处理一份
  临近过期的历史深度再启动前进。初次确认、搜索和低质量路径保留历史对齐策略。
- 在测距和控制决策前发布不可变 ROI 快照。Depth 线程仍须等待同一控制锁，
  不能越过当前视觉决策；如决策随后请求停车/制动或进入搜索，锁内检查拒绝该
  已复制快照。视觉收尾不再重复替换同一帧快照，避免撤销刚唤醒线程持有的版本。
- 正向或倒向非零授权提交前预留 `max(30ms, 电机最小下发间隔)`，当前为 50ms。
  不满足时不启动/加速、不刷新原授权时间；已有同向授权可降速但继承原截止时间。
  若新请求与旧方向相反，撤销旧运动并输出零，不能因新换向暂缓而继续旧方向。
  显式零速不受这个正速度准入条件限制。被限幅/暂缓的输出仍反馈给 PID 抗积分饱和。
- 没有增加固定 sleep、确认帧数或等待窗，没有延长 RGB/Depth 的 180ms 期限。
  不修改 ReID、PID 增益、60% 上限、实际车轮换向保护或转动时速度前馈资格。
  运动补偿需独立验证，不能借本次时序修复直接放宽原有 5°/s、10° 方位保护。

新增日志：

- `vision_depth_priority`：视觉测距是否走 latest、CAP、UID、ROI 年龄和物理样本年龄。
- `depth_linear_admission`：剩余/所需下发预算、旧授权及 `defer_positive`、`reduce_only`
