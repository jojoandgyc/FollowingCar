# 距离 PI 主控、独立制动与统一恢复

## 范围与使用

本轮依据用户确认的方案替换正常前进控制。主配置
`car_control_modular/config/reid_runtime.ini` 的 `[distance_pid] control_mode=distance_pi`。
继续使用 `./run_request_0428_modular.sh`；无需设置额外试验环境变量。

单次回退到此前的追赶曲线：

```sh
FOLLOW_DISTANCE_CONTROL_MODE=approach ./run_request_0428_modular.sh
```

`FOLLOW_DISTANCE_CONTROL_MODE=legacy` 可选更早的 PID 模式，并非本轮的直接对照基线。
正常 PI 不叠加旧 P/I/D、20RPM起步偏置或人速前馈；原倒车保持独立资格和旧 PID。
身份识别、搜索策略、横向 PID、深度数值过滤和电机线程未在本轮调参。
后续已按用户要求将正常前进授权扩展至最多250ms，180～250ms仅受限接续，
新控制样本和积分间隔仍180ms；倒车仍180ms。详见 `depth_authority_250.md`。
250ms条件式ROI窗口、危险停车、写入前截止检查保持。
独立深度 shadow 仍没有电机权限。

## 控制职责

每个新的、可信、同UID物理Depth样本至多积分一次：

`e = distance - target_distance`

`b = clip(b + Ki * effective_error * physical_dt, 0, integral_max_m_s)`

`v_request = max(0, Kp * effective_error + b)`

有效误差在现有3cm死区内为零、死区外减去死区宽度；死区冻结积分增量，不清除
已学到的补偿。SI单位统一计算，最后按轮周长0.816814m换算RPM。
首轮候选值Kp=1.0/s、Ki=0.4/s²、I速度上限0.8m/s（约58.8RPM），D不加入请求。
这些是待验证参数，不是实车标定结果。总上限仍200RPM，不能把支持的硬件量程当成安全实测车速。

制动独立于人速前馈资格：使用新鲜同步编码器、原始深度短窗与现有转动界限，
同时限制已发生的接近和新命令可能造成的接近。可靠相对运动时允许
`ego_velocity + conservative_range_rate + allowed_closing_velocity`，再受总预算和近距保护限制。
因此零误差且人车同速不必把整车速度裁零；真实靠近时仍提前减速。
缺可靠相对速度则使用保守静止目标/显式编码器上界，不伪造人速。
0.40m/s²减速度和0.20s响应预算是模型假设；目标突然停下时，不能保证任意车速都守住精确1.5m。

PI只保留一条加速斜坡：普通测量失败不会重启旧25/45RPM恢复阶段。
真正失权后，必须等新可信Depth；恢复起点取新鲜实测轮速，不把盲区时长兑换成提速额度。
无匹配人速不再套旧60RPM总预算，正常输出仍受统一制动/加速/运行总预算约束。

## 积分、暂停与授权分开

- 重复或倒序样本不积分，不推进执行加速时间，不刷新授权。
- 首样本与超过180ms的物理间隔不补积盲区；即使采集间隔较短，处理时上一授权已经过期也按断档恢复。
  同UID积分记忆最多保留350ms，起点是最后真实样本。
- 普通短缺测保留记忆，不等于续期电机授权。180～250ms只有原授权且通过制动余量检查才允许接续；
  超过250ms仍停前进。
- 新样本由于下发预算不足没有获得授权，只撤销本样本正向积分增量，不把旧积分当成零指令反复清空；
  未下发请求不能成为下一次加速的起点。
- 实际授权在180ms期限内被提前撤销，也暂停执行斜坡。内部记忆可保留，但下一张新深度须从可信实测轮速恢复。
- 正常加速/速度上限触顶时停止向饱和方向累积；可靠制动上限低于旧积分贡献时有界释放旧积分。
- 到位且实际低速、相对运动也低，连续新观测确认后清除残余补偿，避免停后爬行。
- 身份改变、明确危险、长期失证据清状态；旧积分不能授权新UID。
- 最终批准速度回写下一样本的斜坡起点。同样本更严格限幅可修正，重复回写不重复扣积分。
- 百分比下发向下取整，绝不因取整穿越制动上限；正常一个量化单位以内的损失不反复冻结新增积分。

主控制与执行器仍分工：PI使用物理采样时间，执行斜坡使用处理/批准时钟；
20Hz执行器合成纵向和横向，仍在下发时复查授权。没有新增串口读取、阻塞等待或录像处理。

## 日志与指标

启动应出现 `distance_control_mode mode=distance_pi`。
逐样本新增 `distance_pi`：error、P/I、限幅前请求、批准参考、制动上限、制动来源、
物理dt、积分冻结与状态。`distance_pi_pause` 区分记忆保留和旧授权是否可能仍有效；
`distance_pi_admission_rejected` 记录新请求未被授权的原因；
`distance_pi_authority_suspended` 记录提前撤权后的执行暂停；
`distance_pi_limit` 区分正常百分比量化和真正下游限幅造成的积分回退。
原 `distance_pid`、`depth_linear_limit` 与轮端反馈继续用于请求→批准→实测对照。

人速估计只诊断，`tracking_base=0` 是本模式设计，不可把100%无匹配基速当性能退化。
也不能仅以积分增大或停车比例降低判断改善；必须比较移动误差、速度连续性和站定过冲。

基线：`run_20260918_000408_45885_d1453311`，移动CAP71～419。

相近起点/路线/走速下先移动20～30秒再站定，明确移动起止CAP。站定单独统计进入
1.5±0.15m的时间、最低距离和再次起步；测试观察线为最低不低于1.40m，但这不是硬件保证。
出现更大过冲、误关联、异常高轮速应停试并回退，不以移动误差改善抵消安全恶化。
先做直线、空旷、低速、有人可急停的验证，再验证正常差速转向。

```sh
python3 tools/follow_metrics.py run_request_0428_modular_logs/新运行目录 \
  --cap-start 移动开始CAP --cap-end 站定CAP --target-distance 1.5
```

历史日志回放只能验证控制分支，不能证明改变指令后的距离轨迹。简化闭环模型也不能替代实车。
本轮不启动电机、相机或串口；回归结果记录在项目交接文件。

## 本轮无硬件验证

PI初版新增138项测试通过；当时标准 `python3 -m pytest -q tests` 为2484通过、2项既有搜索方向失败，
没有新增失败。旧P试验的3条警告是预期行为：`FOLLOW_DISTANCE_P_TRIAL` 不再调整新PI的正常前进。

拒发后恢复、处理时旧授权过期、提前撤权、倒车及倒车释放、不可转向目标的前进禁令与原安全退距。
编译、启动脚本语法和差异空白检查通过。以上不代表已验证实车控制效果。
