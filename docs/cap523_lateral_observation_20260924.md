# CAP485–555：纵向失权后的转向接续与重复补看

## 基线与范围

基线 `run_20260924_194423_35607_3a2cbcce`：CAP523 的纵向接近速度证据因
转动补偿不确定性退出，前进由约 66RPM 降为 12RPM 再到零。
此时双轮仍向前转，直接发送右轮反转指令不安全。旧交接额外要求两轮
都停稳；CAP533 普通补看和 CAP542 可信重试又分别发起一次约 300ms 停车。
CAP544 已输出 UID1，但重试只检查停稳后的图像，继续等到 CAP549 超时。

本次不改 RPM、纵向制动模型、身份阈值、采集期限和电机控制器参数。
没有启动相机、电机或实车运行。既有搜索交接、转向及其他工作区改动保留。

## 修改

### 纵向减速与横向接续

`ForwardLossHandoff` 增加受限交接：当前目标处于可信可控状态且仍有新鲜
横向授权时，在实际零速命令写出后，需要反转的内轮由两条不同的新反馈
确认已停稳（绝对值 ≤1RPM），外轮仍沿正确方向减速，可恢复当前原地转向。
两条反馈间隔 ≤150ms，外轮不得明显加速，允许 1RPM 测量波动。
此路径仅处理单轮请求不超过 10RPM、外轮反馈不超过 200RPM 的零均值转向；
不扩大当前配置的轮速或差速上限。

输出仍是当前对称转向请求，例如前进归一 `+8/-8`，绝不是无纵向授权时
构造 `+16/0` 的前进弧线。底层过零保护、最终 UID/横向时效/版本检查和
危险停车不变。低质量目标不走这条新交接。实际零速写入时间从统一写入点
回传，不能拿请求零速的时间充当电机已经收到零速。

因此这不是消灭所有零速：CAP523 那样内轮还高速前滚时仍需先制动。
本次去掉的是“内轮已停、外轮还在正确方向减速时，额外等待外轮归零”。
原始纵向证据退出和电机响应滞后没有被阈值放宽掩盖。

### 补看预算与退出

- 同一搜索轮次、同一 UID，普通补看开始即消耗可信重试的停车预算。
  重试是普通补看未运行时的备用入口，不再接着增加独立的 300ms 停车。
  不同候选的普通探测策略未全局删除；新搜索轮次/UID仍有新预算。
- 当前身份库已经输出目标 UID，且检测质量、几何和同帧同检测框的身份
  竞争证据都通过时，立即结束普通/重试补看，交回正常控制。
- 核验使用真实采集帧、时间戳和当前输出 UID；低 ReID 距离、UID0、过期/
  重复/乱序图像、多人竞争、明确矛盾不能冒充已经确认。
- 此出口只清理补看状态，不直接赋予 UID、写模板、恢复旧轮速或授权前进。
  未确认候选仍需停稳后的新图像，或在原有绝对期限超时退出。

新增诊断：`forward_loss_inner_stopped_turn_ready` 和
`search_observation_confirmed_release`（明确 `motion_authorized=False`）。
后者表示可以重新走正常控制，不代表已经下发电机指令。
