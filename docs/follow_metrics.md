## 最新修正：CAP316～368 的三个时间字段（2026-09-16）

上一轮的“将整个电机授权期限取为Depth与FF期限中较早者”存在衔接缺陷：
重复深度拿授权时间当作已接受样本时间比较，CAP316/322/335/345因而错误清零。
下文“本轮实现边界”是上一轮记录，其中这一条已被本节替代。

现在 `DepthLinearTiming` 不可变记录绑定到确切授权快照，分别记录：

- `accepted_depth_timestamp`：只有实际提交的观测才记录，去重用它，不用已处理
  watermark（后者可能包含因执行预算不足而拒绝的样本）。
- `feedforward_timestamp/expires_at`：限制前馈附加输出。到期不得继续保留旧FF。
- `depth_expires_at`：限制实际纵向授权，仍不超过对应Depth采集时间后180ms。
  非新鲜的减速保持只能继承原截止时间，不能以新处理时间续期。

新的可信深度提交时，预先从**同一次**PID结果的P/I/D项计算普通距离控制输出，
不重新积分、不重新求导、不使用旧FF。它同时受普通前进启动距离、普通Depth限幅、
本次已批准速度限制。FF到期时，队列消费和电机写入锁内共同复核并降至该输出；
若接近保持距离、没有合格独立输出或Depth也到期，则仍归零。显式停止、危险、
目标/UID变化、搜索及低质量状态不能通过这个降级路径恢复前进。

此次不修改匹配基速40RPM、总速度60%或P/I/D，不增加IMU补偿，也不延长180ms。
真实采样间隙仍需要后续实车/时序剖析，不能宣称已完全实现30Hz有效运控。

## 每轮使用相同口径

工具只读取已有日志，不启动模型、线程或电机，不改写运行日志：

```bash
python3 tools/follow_metrics.py run_request_0428_modular_logs/run_20260916_140524_7803_d53bab23 --cap-start 938 --cap-end 1088
```

不提供 CAP 参数时统计整轮。输出为 JSON，含 `schema_version=1`、运行目录、实际
CAP 范围、时间范围、分母和限制说明。运行目录最好明确指定，避免新启动覆盖“最新”指向。
需要对比时，使用 `--compare-run 旧运行目录 --compare-cap-start 起始CAP --compare-cap-end 结束CAP`；
当前片段仍由 `--cap-start/--cap-end` 指定。输出 previous/current/delta，不自动宣称改善。

- CSV：只统计带控制编号且已选中目标的记录；控制编号去重，未处理采集帧不算缺距。
- 距离误差相对日志 PID 的唯一目标距离计算；目标设置混杂时输出未知，或明确传入
  `--target-distance 1.5`。缺失距离不插值，也不当作零误差。
- 距离达标带默认 ±0.15m，可用 `--tolerance` 调整。这是验收带，不是控制死区。
- 控制/电机窗口：起始 CAP 采集时刻到结束 CAP 采集时刻再加180ms，覆盖尾帧处理。
  可用 `--tail-sec 0` 严格截在采集时刻。日志按 Asia/Shanghai 解读。
- 有效深度频率：该时间窗口内接受的新物理深度样本去重，(N−1)/(末样本−首样本)。
  不是相机采集频率，不是电机写入频率，也不是仅按 evidence CAP 筛选的频率。
- 电机写入按相邻写入间隔加权，继承窗口前最后命令，右轮转换为前进正号；缺少
  命令的时间记未知。零指令比例不代表车身真正静止的比例，写入后惯性仍可能存在。
- 编码器数值是可信日志样本的算术均值，不是连续里程计积分，不能据此精确计算人速。
- 前馈按 PID 更新次数统计，另外区分 fresh / bridge / none；旧日志正前馈记
  legacy_matching。不能靠增加过渡记录来宣称真实速度估计有效率提高。

## 本轮实现边界

### 短暂转向：固定期限前馈过渡

仍只有 |yaw|≤5°/s、|bearing|≤10° 的可信深度/轮速用于**重新估计**目标速度。
5～15°/s 短转时可使用最近已通过验证的匹配基速，附加基速随年龄线性衰减；
从原证据采集时刻计算最长180ms，不能由新深度或重复调用刷新这个起点。
转动期间清空速度微分链，回到低角速度后仍需两个新物理样本重新建立估计。

每次过渡都要求新鲜可信深度、同UID、无危险、可信新鲜轮速、方位仍在±10°内；
原始距离相对原证据下降超过3cm、增加超过30cm、接近安全距离或更大转动均拒绝。
输出不能高于上次批准的PID速度；执行层还要求已有未过期的同UID前进授权，
不得重新起步、恢复已撤销速度或将后退变前进。电机授权期限取深度与原前馈证据
中更早的期限，所以队列等待不能把过渡延长到180ms以外。

这不是已经验证的车体转动补偿。持续大转动仍退回原策略，不抬高总速度、P/I/D
或 ReID 阈值；运动补偿和匹配基速40RPM上限留待这轮指标与轮周长校准后评估。

### 恢复限速：只合并明确的短时调度间隙

仅明确 `depth_detector_bbox_stale` 或有物理来源的重复/旧样本，且同UID、上一
可信样本仍在180ms内、无危险时，保留原恢复斜坡起点。该状态本身不授权前进，
当前无有效深度时原来的撤销/零纵向逻辑不变。
新深度在原期限内接续且距离变化≤30cm，继续原斜坡，不重新等待200ms。
若超过期限、换UID、距离跳变、有效像素不足、背景保护或危险，则重启原25/45RPM
恢复流程。没有把所有深度无效原因统称为“短暂异常”放行。

新增日志：`longitudinal_motion_bridge`、`distance_pid matching_source`、
`depth_recovery_gap action=pause/resume/restart`、`depth_speed_recovery_limit`，以及
`depth_linear_limit authority_sample_ts`。后者区分物理新深度与实际授权截止依据。
