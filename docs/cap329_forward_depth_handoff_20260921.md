# CAP234–382：差速前进接续修复

## 边界

以 run_20260921_174920_42173_03d1d34d、CAP234–382 为基线，`tail_sec=0`。
不改 PID、RPM 上限、ReID、搜索方向、深度过滤阈值或 250ms 物理授权截止。
本轮未操作实车、未启动控制程序、未修改驻车电流。正常交接继续使用零转速，
不发送 NORMAL 驻车。独立危险停车不受影响。

## 已启用的执行修改

1. **前进失权先减速，不自动请求原地反转。**
   - 仅由真实写出的双轮前进包建立交接状态，不由队列中的请求建立。
   - 失去前进基速后输出 0/0，保留当前有效横向意图，但不建立旧的混合正负过零等待。
   - 新的前进授权恢复，立即重新组合最新纵向和横向请求，再经过现有反转检查。
   - 若仍需原地转向，须两次不同的新鲜双轮反馈均不超过 1RPM；重复反馈不能累计。
   - 不固定等待数百毫秒，不用超时强制放行。缺失、过期或真正反向反馈仍保护。
   - UID/搜索范围切换清理交接；没有前进历史的原地转向不走此新增分支。

2. **180–250ms 延续从二选一增加“降低原速度上限”的分支。**
   - 原制动检查通过时行为不变。
   - 仅原检查因制动余量拒绝时，检查不超过 100ms 的可信双轮反馈。
   - 仍按目标停止估算：扣除从原 Depth 采集至今的最大行程、反馈年龄预算、
     响应延迟和制动距离。实际轮速制动余量不足，仍撤销。
   - 余量允许时解出更低 RPM 上限；不超过原授权，随原样本年龄只降不升。
   - 电机读取、晚到 Depth 收紧授权使用同一函数，避免一个分支批准、另一个再次清零。
   - 不产生新测量、不更新 PID、不刷新任何授权时间；失效授权不能复活。
   - CAP329式离线输入：距离 2.662m，原请求 100RPM，反馈 34/32RPM，可降为
     约50多RPM的模型上限；反馈100/100RPM时余量不足仍拒绝。
     这是代码/模型结果，不是实车制动能力已验证。

## 转动深度关联：本轮仅在线旁路验证

现有深度旁路的相机模型明确标记 UNVERIFIED，因此不能直接把补偿框接到前进授权。
本轮新增独立 `roi_turn_validation`，即使组件跟踪种子失败，也能检查以下链路：

- 使用已缓存编码器轨迹，分别内插 RGB 采集时刻和真实 Depth 采集时刻的位姿；不外推。
- 投影原 YOLO 框，考虑编码器旋转和前进位移，限制时间、角度、位移和裁切幅度。
- 用当前 Depth 的三个互不重叠躯干区域验证：至少两区域有足够像素支持预期距离，
  区域间距离差也必须合格。纯背景、单区支持不会按这个标准通过。
- `candidate_consistent` 只表示候选深度一致，不代表身份确认或校准通过。
- 沿用后台线程和降采样缓存，不新增串口读、主循环聚类或同步快照写盘。
- 所有记录保持 `control_allowed=false`、`motor_authority_created=false`。

**因此本轮尚未消除“转动时旧框失效”这个上游瓶颈，也不宣称修复了全部断档。**
下一轮应核对补偿框与 RGB/深度人体轮廓，确认未跟背景/他人，并核对新增耗时后，
再决定是否开放窄范围受限测量接口。现有5°/s门控未删除。

## 配置和回退

`[lateral_intent] follow_forward_loss_handoff_enable=true`；置false只关闭新交接。
`[astra_depth] continuation_speed_cap_enable=true`；置false回到原延续制动二值判定。
两者库默认关闭，运行INI显式启用，真实配置加载和主程序绑定均有回归。
`follow_cross_brake_mode=zero`，本轮实际跟随设定仍为1.4m。

物理授权截止、晚到Depth同策略、真实配置绑定、投影符号和旁路不能授权等。
