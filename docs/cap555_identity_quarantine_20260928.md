# CAP555 前后的身份丢失：部分接回漏接强全身隔离证明

来源：`run_20260928_223853_35353_20b3f2ee` 的 `reid_diagnostics/events.jsonl`、保存的 PNG 裁剪和主日志。

实际首次身份抖动出现在 CAP516，近期可比躯干距离 0.425 超过确认阈值 0.40；
CAP531 接回后，CAP542、549、554 又短暂丢失。CAP557–564 仍有 UID1，
持续丢失从 CAP566 开始，躯干距离 0.408；CAP575 达到 0.484，成为可靠局部反证。
因此不能把 CAP555 后描述为检测器始终没有检测到人，也不能直接放宽 0.40 阈值。

根因发生得更早。CAP390 以部分外观接回 track2 后，模板隔离正常启动；
`IdentityBank._continue_observed_partial` 提前返回 `mapped_late_continuation`。
该函数只让“同一近期模板全身≤0.30、躯干≤0.26”的区域配对返回正常复核，
漏掉了原本就存在的“强全身≤0.20”隔离证明入口。
外层把这个提前返回按未完成正式复核处理，隔离进度始终为 0，近期模板一直被冻结。

CAP415、417、419 的授权全身距离分别为 0.18353、0.17363、0.18505，
均已包含近期模板距离下限；可比躯干分别为 0.38030、0.37147、0.34679，
当前强质量、新帧、几何和身份竞争也通过。它们本可完成原有三帧证明，
但旧代码均报告 `not_high_quality_strong`，没有任何写库机会。

修复仅补齐这个入口：已确认的部分接回候选，在退出搜索、竞争和几何检查通过后，
若当前匹配来源为 strong、近期躯干为 match，且授权全身距离满足原隔离阈值，
交回既有正常身份复核。授权距离继续使用历史匹配与近期 floor 的较大值。
没有放宽 0.20 强全身、0.40 躯干确认、0.30 躯干写库、模板新鲜度、质量或控制授权。
未知/矛盾躯干、候选自身连续、历史低距离、重复帧均不能构成新资格。
