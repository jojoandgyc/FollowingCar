# Depth 与外部 UVC RGB 坐标检查

本次仅修复 Depth 输入方向与旧样本重复计算，不修改 RGB、左右电机定义、
PID、背景保护、跳变确认或距离上限。

## 启动与唯一转换点

1. 开启并检查 depth_to_color 配准。
2. 对 OpenNI Depth 和配准用 Color stream 显式请求 `mirroring=False`，读回状态。
3. Depth 启动后再读回，防止驱动在启动时重置属性。
4. Color 未镜像且 Depth 未镜像：不做软件翻转。
5. Color 未镜像且 Depth 仍镜像：仅在采集入口做一次 `depth[:, ::-1].copy()`。
6. Color 仍镜像或任一必要状态无法读回：明确报错，拒绝启动 Depth。

硬件配准不代表镜像一致。上述坐标目标是假定外部 UVC 未镜像，仍需实机画面
验证，不能仅凭 SDK 属性宣称标定通过。禁止在 ROI、控制代码或回放时再盲目翻转。
日志记录设置前、设置后、启动后的状态，以及 `software_flip_x`。

诊断 `observations.jsonl` 和 NPZ `metadata_json.orientation` 记录坐标空间及变换。
新的 `depth_mm` 是测距实际使用的、方向归一后的 uint16 毫米数据；无效值和数值
完全保留，若软件翻转过可逆向重建 SDK 输入。旧快照无 orientation 元数据，不能
自动假定已归一，也不能对新快照再套一次历史翻转。

## 无电机画面检查

先退出主跟随程序，并禁用电机电源。本脚本不打开电机串口，也不会停止其他进程。
在小车图形桌面终端运行：

```bash
cd /home/topeet/Desktop/rk_car_runtime_module
python3 tools/check_depth_rgb_alignment.py --live
```

默认使用项目当前 640×480、30 FPS、YUYV 和 Astra UVC by-id 节点，预览 45 秒。
若实际相机配置改变，通过 `--device`、`--fourcc` 指定对应设置。
让人站在左、中、右位置，各静止约 2 秒，核对三个面板的人体轮廓是否位于同一侧，
躯干是否大致重合。此预览按到达时间选择 Depth，不是曝光同步标定；移动边缘、
遮挡空洞和少量配准误差应与“整幅左右镜像”区分。按 q 退出。

如果仍反向、存在大偏移、或镜像属性不支持读回，先保留报错和预览结果，不能解除
保护直接启动跟随。左/中/右通过后，再低速测试并统计“选中目标但距离为空”比例。

## 旧样本快路径

重复、早于可信锚点、早于待确认观测的 Depth，在区域聚类前返回保持结果；不续期
锚点、不累计确认、不产生新的纵向 PID 授权，保持值也遵守原有 `hold_sec`。
`roi_scan_skipped=true` 表示这次没有重新采样，像素/区域统计为零并不表示相机断流。
较新样本失败后，尚未计算且晚于可信锚点的历史对齐样本仍可恢复测距，不按处理顺序
一律丢弃。背景保护和物理速度检查继续生效。
