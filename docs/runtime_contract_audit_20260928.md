# 运行边界修复（2026-09-28）

本轮针对代码审查可复现的问题修复，不调整跟随距离、PID、RPM、ReID
阈值或深度授权期限，也没有启动实车。

## 模块责任

- `request_0513_modular.py`：采集、线程生命周期、控制状态发布及退出协调。
- `rk_vision/tracker.py`：本帧候选元数据和 UID 竞争证据的生产者。
- `rk_vision/identity_bank.py`：身份接续、拒绝及候选资格；不是电机授权。
- `rk_vision/reacquire_quarantine.py`：接回后模板学习隔离；不是新的身份来源。
- `car_control_modular/action_runtime.py`：最终运动执行、锁后复核和停止策略。
- `car_control_modular/mssd_motor.py`：双轮串口事务与持久写故障状态。

## 本轮改变

### 电机故障与退出

双轮速度只写成功一侧也属于整次运动事务失败。首次失败独立尝试每轮清零、
每轮紧急 STOP；一次异常不能跳过另一轮。随后禁止非零速度、进入速度模式和
普通驻车解除，零转速请求也不能覆盖 STOP。必须人工排查并重新启动；没有
自动恢复运动。

安全停车自身发生一侧写失败时，同样必须尝试另一侧、锁存故障，重试仅写
STOP，不再插入速度命令。串口写入成功不是实车停稳证据，日志保留
`physical_stillness=unverified`。

退出先锁存禁止运动并直接尝试安全 STOP，再等待线程和清理。信号回调只
设置退出标志，不在可能被中断的锁内重入电机 I/O；动作线程独立响应该标志。
旧运动包在等待电机锁后再次核验退出状态。深度线程未退出则保留引用，
清理不能无限等待共享控制锁。串口驱动本身阻塞仍是限制，不承诺硬实时停车。

### 身份证据一致性

全身证据已满足原强匹配条件时，辅助躯干证据改善不再将证明类型切换成
区域替代证明并反复清空隔离进度。区域替代证明仍单独满足原连续帧数及时间窗。

严格、软、晚到、弱候选和跨侧观察统一核对本帧 UID 竞争证明；UID、帧号、
检测来源索引和候选数量必须对应。其他人 YOLO 检测分数变高本身不构成身份
矛盾。多人缺少有效竞争证明仍拒绝；反方向、几何矛盾及模板隔离保护不放宽。
检测旁路的候选数与同帧证据生产者统一，不用筛选后的数量冒充原始候选数。

### 采集与并发

主 RGB 帧先入控制队列，再提交录像和方向旁路。旁路提交异常记录并禁用
对应旁路，保留资源引用用于退出清理；不能悄悄切换成第二个相机读取者。
采集线程异常、死亡或持续无新帧触发运行故障，不自动重开相机或续期运动。
1 秒采集健康窗口仅是故障报警，不改变原运动时效门控。

共享控制锁暂不大拆：深度滤波、融合和控制状态仍串行提交。仅把末尾汇总
日志移至解锁后，并增加 `lock_wait_ms`、`lock_hold_ms`、`lock_hold_cpu_ms`，
以及队列发布的 `motor_lock_wait_ms`、`queue_lock_wait_ms`、
`locked_publish_ms`。不能把这一步表述为已解决全部响应长尾。

## 回归入口

```bash
python3 -m pytest -q
```

`pytest.ini` 限定默认收集 `tests/`，30 组原脚本检查通过显式允许名单纳入
独立子进程。真实电机/IIO 工具不自动运行。旧配置、单位和安全策略断言已
按当前生产契约核对；没有为迁就测试而改变实车配置。

## 实车后续验收

下一次正常运行主要检查：接回后的隔离是否能够完成；身份竞争拒绝是否有
对应的 UID 证据；控制锁长尾到底来自计算、等待串口还是队列发布。故障测试
只使用模拟驱动，不在运动中故意制造串口失联。离线通过不能证明跟随距离、
响应时延或实际停车能力已经达到目标。
