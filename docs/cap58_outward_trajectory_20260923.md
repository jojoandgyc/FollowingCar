# CAP58：驻车期间的外移轨迹与低速提前跟转

## 本轮改动

- 近距离中心保持期间继续采集同 UID 的可信检测框，使用真实 capture 时间。
  旧帧不会增加样本数量。连续三张独立图像、两段同向运动才可产生提前跟转证据。
- 开始时只处理小偏差：偏离 1～6°、连续外移 3～60°/s、观测跨度 80～350ms。
  以图像年龄加 150ms（合计上限 250ms）作短时位置预测；预测超出中心释放边界，
  才申请低速原地修正。这是图像相对运动，不是对目标地面速度的估计。
- 提前修正为单轮 2～4RPM，即双轮差 4～8RPM；更低的质量/安全上限仍有效。
  此上限贯穿主控制、快环、slew 输出和普通动作下发，不能被旧的 5RPM 起步下限抬高。
  正常前进差速、远处纠偏和已有预测反打的上限不变。
- 中心释放带内提前解除 NORMAL 时，要求当前同 UID/同 capture 的有效轨迹，
  且三张图像均采集于实际 NORMAL 完成之后。沿用严格停稳反馈检查及 NORMAL 后
  至少 100ms 保持；不提前清驻车电流，不恢复旧前进授权。
- 证据通过不可变对象传入快环，仅在原有视觉意图期限内使用；不延长 TTL，不
  排队执行未来动作，不设置 0.5 秒最小通电时长。新的静止、回移、抖动或无效
  图像撤销提前补偿，恢复原有位置/预测减速控制。
- 低质量目标不能用该入口恢复运动；贴边仅供制动的样本不能混入恢复后的
  外移启动证据。原有普通反转保护、危险停车、5A NORMAL / 恢复前 0A 流程保留。

## 配置与观测

INI `[steering_pid] outward_lead_enable = 1` 开启，设为 `0` 回退提前跟转功能。
配置类默认关闭，运行 INI 显式启用。查看 `outward_trajectory_lead` 日志中的
capture、UID、位置、画面速度、实际请求修正与双轮差；中心带内成功释放的
`near_yaw_park_released` 原因后缀为 `outward_trajectory`。

验收重点是首次小幅非零输出是否提前、外移时是否保持连续，以及首次过中心
幅度是否增加。2～4RPM 能否克服真实电机响应迟滞尚需实车验证，不能由软件测试
保证。没有操作实车或修改电机硬件参数。
