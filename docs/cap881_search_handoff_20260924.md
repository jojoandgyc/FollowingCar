# CAP881–911：搜索接回停车与低分补看

## 证据与边界

基线：`run_20260924_191209_31661_0193d466`。CAP791 接回留下的
首次回中停车状态，到 CAP867 仍存在，并触发 `candidate_predictive_stop`。
到 CAP887 才解除，耗时 1036.8ms。随后有 60/40、86/66 的前进归一轮速
下发；不是整段右转指令为零。CAP900/901 的 0.1402/0.1107 探测候选
又触发补看零速，CAP904 恢复。串口原始 7/7 实际为前进归一 7/-7。

## 本次改动

- 搜索结束后，只有新的、及时的同 UID 确认观测能结束交接状态。
  当采集时间距接回达到 750ms，改由普通视觉转向控制接管；无新图、重复图、
  旧图、身份未确认均不能仅靠计时恢复运动。750ms 不是运动授权期限。
- 同 UID/原轨迹连续三帧、短窗内位置及面积连续、同侧持续远离中心时，
  可更早结束交接。候选自身连续不能获得身份，此入口只用于已确认目标。
- 结束的是旧搜索的停车义务及其临时轮差上限，不是直接下发转速。
  普通控制的回中制动、轮子过零、障碍/身份/深度保护继续生效。
- 已经进入的停车不强行解除；搜索中的未知候选、首次接回残余转动的停车
  路径保留。因此未全局删除 500ms 驻车或 1RPM 停稳要求。
- 无当前身份支持的 probe，置信度低于 0.15 时只保留原始诊断，不能进入
  候选控制或停车补看。当前可靠身份支持的低分框，以及其他合格候选，
  仍可有界补看。YOLO 检测、ReID 阈值、身份排除和模板权限不变。
- 搜索诊断补充前进归一双轮转速、反馈采样时间、双轮位置，并标明原字段
  为串口原始符号。全部读取现有反馈缓存，不增加串口读取。

响应还是反馈异常，未改符号、增大 RPM 或删除保护来掩盖它。
