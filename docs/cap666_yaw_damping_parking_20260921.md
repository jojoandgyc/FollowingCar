# CAP666–1222：位置主导转向、提前减速与驻车释放

## 修改依据

基线为 `run_request_0428_modular_logs/run_20260921_194828_52013_7503fc6d`。
约 29.75 秒内，统一轮速下发左右换向 14 次，零轮速指令时间占比 34.54%，
过零等待造成零指令约 4.35 秒；有效双轮前进请求被置零 0 次。
这里统计的是指令，不等于车身已经静止。

5 次中心驻车释放都使用了实际 NORMAL 下发前采集的图像。
例如 CAP1128 驻车于 19:49:31.422 下发，CAP1131 采集于 31.391，
却在 31.508 用于解除驻车。视觉延迟平均约 96ms，P95 约 139ms。

## 本轮修改

1. 保留 `image_error_only = true`，新增 `image_brake_assist = true`。
   画面误差决定轮差方向，不恢复角速度内环、反打或启动脉冲。
   角速度只可减小同方向修正，不能增加幅度、决定方向或授权前进。
2. 制动反馈必须可信、年龄不超过 100ms；原始/滤波角速度同号、
   差不超过 10°/s、幅值不超过 90°/s，双轮反馈与时间戳须有限。
   使用两者绝对值中较小者，估计图像延迟及停车阶段的转角。
   沿用现有 60°/s²、50ms 响应、1.25°余量，并非实测制动能力认证。
   反馈不合格时退回位置曲线，不依据滞后滤波值清零远处修正。
3. 修正幅度从 3°中心带外的 0RPM 连续增长，10°达到原上限；
   取消该模式在中心附近的 5RPM 台阶。原最大轮差限制不变。
   进入中心后，偏离超过 4.8°才释放位置保持（新增释放余量 1.8°）。
4. 零轮差明确占有主视觉周期，不能落入旧边缘转向兜底；
   有效前进时保留纵向基速，不把零轮差变成整车驻车。
5. 需要驻车时，动作线程成功完成 NORMAL 写入后才记录 `stop_sent_ts`。
   读取现有轮速缓存，无新增串口查询：两个不同采集时间的可信双轮反馈，
   双轮均不超过 1RPM、安静跨度至少 40ms、最新反馈年龄不超过 150ms。
   重复缓存不增加计数；移动、过期、乱序或反馈间隙过长会撤销停稳证据。
6. 驻车释放还必须有停稳证据建立后采集的新图像，原有身份、危险、
   新鲜度和事件检查仍有效。单纯横向释放需离开扩大的中心带；
   新的合法纵向启动或显式搜索交接不受中心带限制，但仍需上述新图像与停稳证据。
   不设置“等待足够久就强行解锁”的超时；没有可信反馈时保持驻车并记录原因。

本轮不改纵向 PI、深度过滤、深度授权期限、ReID、搜索转速、驻车电流，
不取消实际车轮反向过零保护，也不撤回前一轮有效前进接续修复。
关闭 `image_brake_assist` 可对照旧的位置转向曲线，但不会取消驻车释放修复。
