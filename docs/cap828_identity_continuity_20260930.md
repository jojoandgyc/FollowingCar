## 统一接续规则

新增纯判断模块 `rk_vision/verified_continuation.py`，由身份库构造证据，身份后置检查复用同一结果。

1. **接续权限必须有来源。**只有内部已经确认的 strong/partial 接回才能进入；原始轨迹编号相同、候选自身连续、外部 metadata 都不能自行产生权限。
2. **每帧仍需当前证据。**新鲜且强质量、相同原始轨迹、新 CAP 和采集时间、身份竞争通过、局部几何连续、转动补偿有效；已成立的身份矛盾、排除和撤销优先。
3. **使用真实近期的同一模板配对。**全身与躯干来自同一已批准 CAP、时间、轨迹和框；临时形状滞回、尺度/姿态保持、长期代表不能冒充正常近期配对。
4. **不同证据承担不同职责。**partial 来源的近期全身支持不超过现有 `match_threshold=0.38`；strong 来源仍不超过现有软匹配上限 0.30。配对模板的全身距离不超过现有绑定复核 0.45，躯干确认不超过 0.40。不能把旧库最小距离拼成“近期强匹配”。
5. **确认与模板学习分开。**这条接续路径不写库、不自行解除隔离、不替换保护搜索锚点。只有原有独立强证据或更严格同模板配对条件通过，才能走正常隔离解除/学习路径，避免图库永远冻结。

配对全身与近期全身支持不是同一指标。例如 CAP840 近期全身最小距离约 0.352，而 CAP414 同模板全身距离约 0.430、躯干仍合格。前者满足已有普通匹配范围，后者满足已有绑定复核范围；两者均不被升级为首次强匹配。

## 灰区、失权与再次接回

- 躯干 0.40～0.45：只保留最后可信身份来源并停车补看，**UID0、不写库、不更新可信方向、不续深度或电机授权**。
- 补看截止时间从最后合格采集算起，至多 350ms，包含处理耗时；灰帧不能滚动刷新期限。
- CAP 和采集时间双水位覆盖已消费灰帧；同帧重新计算出更低距离也不能升级成新证据。
- 超时、明确矛盾、竞争失败、不可比裁剪：退出本接续，交还正常受保护的核验流程。
- runtime 在非搜索、单候选、当前目标且截止时间有效时发布现有软停车；清除纵向上下文、深度授权和横向意图。危险处理仍优先。
- `preferred_search_mapped_late_wait` 输出 UID0 时撤掉旧 raw-track 绑定，保留待确认计数、旧保护锚点和负面记录。下一帧进入同一候选确认链，而非再走已绑定的 0.20 初次入口。确认后重新隔离。

接口审查同时修正了参数与 metadata 的质量一致性：任一路明确拒绝优先，质量等级采用较弱的一侧；明确换人/中心跳变必须先于接续与灰区补看处理。

晚到候选也不能只靠自身两帧连续消除已有身份撤销记录。但撤销某条错误映射，不等于永久封禁正确目标：独立候选仍可在原可信参考的短时、小转角范围内，以强全身证据、位置/面积吻合、竞争通过，重新走两帧确认。该窄门检查原可信参考而非候选自己的局部轨迹（至多 2 秒、20°、补偿跳变 0.15、面积相似度至少 0.65，全身不超过现有严格 0.20；配置更严格时服从配置）。错误轨迹的持久矛盾不清除，软匹配不享受这条权限。旧 CAP714、CAP874 正确人物返回及错误人物拒绝同时回归。

## 验证方法与结果

分三层验证，不能互相替代：

1. 纯证据/状态边界测试：来源、竞争、几何、模板配对、严格配置、同帧重复、乱序、过期、灰区固定期限等。
2. 完整身份库与 runtime 消费测试：实际调用 `assign()` 和记录消费/零动作发布方法，硬件端点为替身；包含此前正确接回与错误人物回归。
3. 真实保存裁剪回放：使用同一运行的已批准模板，按原模型和预处理提取特征。校验模型、裁剪和特征缓存来源，从日志已确认 CAP830、CAP879 检查点分别开始；不是从零回放整轮运行。

## 实车复验重点

下一轮使用原启动命令，观察正常转身、横穿、短遮挡、多人竞争及出边后返回。重点检查：合格接续是否仍被其他分支撤销；灰区是否在固定期限内恢复且只发零动作；未确认或有空间矛盾的候选能否污染图库；真实侧边裁切后的恢复是否及时。

这轮没有承诺任何角度/遮挡下永不丢失，也未取消无可比证据的保护。后续若仍有拒绝，日志会分别给出接续来源、参考 CAP、配对 CAP、当前证据、固定期限与具体失效原因，避免再次只看单个 ReID 数值。
