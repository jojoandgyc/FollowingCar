# 前进／转向接续修复（2026-09-28）

## 证据与范围

基线：`run_request_0428_modular_logs/run_20260928_190236_10631_26bb29b9`。
既有合成并非只能原地转：CAP1558 已下发逻辑轮速 70/50RPM，CAP1628 为48/68RPM。
这里左右轮是统一前进符号后的值，不是右电机协议原始正负号。

主要中断链路是：转动期间 ROI 处理年龄超过180ms → 无新测距 → 旧授权的附加制动检查拒绝 → 只剩横向请求 → 正在前进的轮子不能立即反向，先归零 → 新测量恢复后再前进。
CAP213、371 保持 UID1，也能出现此链；CAP1561、1631 另有身份待核验，不能将这些停车全部取消。

## 本次实现

1. **Depth 调度不持旧框排队。** Depth30 取控制锁失败时立即返回，按5ms等待预算重试并重读最新上下文；实际唤醒仍受系统调度影响。不测距、不改控制状态、不刷新授权。拿到锁后重查 UID、CAP、快照、停车及搜索状态。测距和融合滤波仍在原锁内，不新增并发写。
2. **有界真实历史深度选择。** 仅真实支持该接口的相机可使用。ROI 处理年龄仍不得超过配置上限且最多250ms；低转动扩展条件不满足时，从缓存原子选择 `capture_ts <= sample_ts <= capture_ts+180ms` 中最新且当前年龄不超过180ms的真实帧。无合格帧不回退窗口外最新帧。采样完成后、底层接受样本前和融合前再次检查时效；重复、旧样本不能成为新测量。
3. **过时执行计划不覆盖新授权。** 等待电机锁期间，如果合法组合轴已恢复，旧撤销计划不再补发0/0；退出停车电流期间，旧原地转计划被新前进授权替代时，使用既有最多一次的重算机制，当次重算两轴。新的输出仍经过身份、期限、危险和实测反转保护。
4. **延续速度语义一致。** 车体平均轮速只判断纵向是否超过原速度界；外轮仍负责保守停车预算。两条旧授权延续路径共用当前反馈检查。既有界值生成、制动参数、250ms上限均不变。

历史帧来自已有 Astra 缓存，无额外相机或串口读取。Depth 的现有时间戳是**主机到达时间，不是曝光时间**；没有将未验证的转动投影旁路接入电机，也没有移动人体框。
保留原180ms关联窗口不代表已经证明转动时绝不会采到背景，多区域／跳变／身份保护继续生效。

## 没有改变的边界

- 不提高前进RPM、轮差或PID参数，不放宽ReID、人体框质量和危险停车条件。
- 新的真实深度才可能更新前进授权；显示保持距离、预测距离、重复帧都不能续权。
- CAP1628 原界58RPM、反馈52/65RPM：均值58.5仍超界，制动预算也不足。此次回归要求它的**旧授权**继续拒绝；减少这类中断依赖新测量及时到达，不靠删制动检查。
- 真正近距离、身份冲突、搜索、深度失效或轮子反转仍可能需要先停再转，本轮不承诺任何场景都可以不停前进。
