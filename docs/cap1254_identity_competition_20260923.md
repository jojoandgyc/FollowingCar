# CAP1254 接回后复核修复

## 已确认的问题

来源：`run_20260923_135749_13752_c7b285c7`。

CAP1249 输出 UID1。CAP1254 的躯干、几何和 UID 竞争仍通过，但 YOLO 置信度差从 0.288709 降至 0.244516，低于 0.25。旧接回复核把该检测分差用于躯干支持资格：撤掉躯干支持后，又因近期全身距离 0.317390 >0.30 进入怀疑。

进入怀疑后的恢复只接受全身 ≤0.20。CAP1261 搜索又切回保护锚点 CAP1065（10.22 秒前）；近期躯干持续通过，却无法启动局部恢复。CAP1254～1295 的 20 条记录均输出 UID0。

## 本轮变化

1. 接回后复核使用身份竞争，而不是 YOLO 检测分差。核对 UID、处理帧、来源检测编号和候选数；多候选缺少当前身份比较时继续拒绝，过期/其他候选的通过记录不能使用。单候选在没有竞争记录时保留原单候选规则。
2. 怀疑记录区分 `evidence_gap`、`appearance_conflict`、`partial_conflict`。旧的无来源怀疑按严格条件处理。只有可靠近期躯干仍匹配、全身没有超过原 mapped 上限、且没有明确几何矛盾的情况，才可记录为证据中断。
3. 证据中断允许可靠躯干参与恢复，但必须有当前身份竞争资格、采集时效、车体角度以及两张新观测。旧参考过期只能启动观察；第二张必须与独立局部轨迹连续。重复观测不累计，断档重启观察。明确外观/几何矛盾不能因此降级。
4. 恢复来源传到下游：已经通过两帧复核的 partial 恢复，不再被搜索映射的全身 0.20 检查重复拒绝。原全身 mapped 上限仍检查。这条路径标为 partial，不释放模板隔离、不写模板。保护锚点不被待确认候选替换。

诊断增加 `reacquire_control_competition_ok/reason`、`reacquire_control_suspect_reason`、`reacquire_control_recovery_source`。原检测分差参数在其他候选入口保持不变，本轮没有全局取消竞争检查。

躯干 0.45 观察上限和 0.34 可靠确认条件保持不变；未修改 YOLO、RPM、距离控制或电机授权时限。

## 验证方法与结果

`tests/vision/fixtures/cap1254_reacquire.json` 保存本段框、真实采集时间、车体转角、候选数、检测分差及匹配距离。测试使用这些数值构造合成向量，经过公开 `IdentityBank.assign()` 接口，不是完整原始特征库或实车轨迹回放。

- 重新启用旧检测分差判断可重现 CAP1254 拒绝；新逻辑下 CAP1254、1256、1259 继续 UID1，不写库。
- 即使继续输入原日志已经进入搜索的状态：CAP1261 只建立观察，CAP1263 两帧确认后恢复；后续样本至 CAP1295 持续通过。保护锚点仍为 CAP1065，模板仍隔离。这里不代表新控制器实车一定会在 CAP1261 进入搜索。
- 新增 24 项回归覆盖缺失/过期/错误 UID/错误候选的竞争证据、明确矛盾、躯干灰区、重复、无角度、过期采集、长间隔及接回后连续性。
- 视觉回归 641 项通过，包括原 CAP874、CAP714、CAP2394 错误人物及 CAP1161 距离模式保护。
- 全套 4236 项通过、3 项原有失败：目标距离配置断言（配置 1.4、测试期望 1.5）及两项搜索方向测试。`git diff --check` 通过。

运行：`OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m pytest -q tests/vision/test_cap1254_identity_competition.py`

本轮未运行摄像头、NPU 推理、串口或电机；没有修改原始日志。实车仍需同时验证正确目标接续和错误人物拒绝，策略回归通过不等于模型误识率已被验证改善。
