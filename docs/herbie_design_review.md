# HerbieAutonomy 设计借鉴与跟随小车改进建议

分析日期：2026-09-16。

## 结论与范围

对照 `/home/topeet/HerbieAutonomy` 与当前 `rk_car_runtime_module` 工作区，重点阅读
Herbie 的 Python 主程序、Arduino 固件，以及本项目活动入口、控制、录像、深度诊断和配置。
本项目存在未提交修改，本报告以当前文件为准，不只依据 Git 提交。
本次为静态代码分析，没有启动摄像头、电机或运行实车验证，也没有修改控制代码。

Herbie 值得借鉴的是现场采集到离线验证的开发流程、可解释的通行区域判断和快速人工接管。
本项目在身份保持、深度可信度、按时间控制、异步录像等方面已有更细的实现，宜增量补齐。

当前实际配置启用视觉、ReID、Astra Depth 和红外，关闭毫米波、超声波及 bunker。
距离融合模块存在不代表毫米波正在参与控制。保留现有视觉＋编码器转向方案；本报告不建议加入 IMU 转向反馈。

## 1. 优先补齐可复现的现场记录与回放

### Herbie 做得好的地方

- `src/Jetson/herbie_autonomy.py:1341` 附近在绘制前复制原始帧；1798 附近分别写 clean/debug 视频。
- `read_video_frame()` 在 1047 行提供录制视频输入，让规划器重复处理同一场景。
- 调试画面显示模式、帧号、候选路径和动力输出，便于定位失败并取对应原图。

### 我们已有的基础与缺口

- `car_control_modular/video_recorder.py` 已有有界异步队列，不阻塞采集和控制；这点值得保留。
- 已有采集帧号、控制帧号、单调时间戳、目标 UID、距离、动作及原因等 CSV 字段。
- 但 316 行附近在编码前调用 `_annotate_frame()`，因此当前 `camera_raw.avi` 实际是带标注画面。
- `depth_diagnostics.py` 已有受容量限制的原始深度 NPZ、RGB 预览和异常事件前后快照。
  这些是有价值的诊断证据，但抽样预览及稀疏快照不能等同于完整连续的传感器回放。
- `tools/rknn_video_smoke.py` 和 `tools/tracker_segment_eval.py` 已支持感知测试和分段评估；
  本次阅读未发现把现场传感器时序、控制决策及动作调度统一复现的完整入口。

### 建议增量实现

1. 在现有录像后台线程中保留真正的 clean 流，debug 流可按需生成；记录每条流自己的帧映射与丢帧。
2. 新增运行清单：代码版本及工作区差异标识、实际生效配置、模型哈希、图像尺寸和标定版本。
3. 统一事件记录：采集与处理时间、身份结果、深度及其接受/拒绝原因、红外、编码器、
   请求动作、最终批准动作、实际发送轮速与反馈。不要用 requested_rpm 代替实际电机输出。
4. 先做控制级回放：记录完整控制输入及异步更新事件，用可注入时钟、虚拟电机后端驱动同一控制逻辑。
   复现实际发生顺序和时间间隔，尤其是深度先到、视觉后到、样本重复和超时撤销。
5. 再做感知级回放：从 clean RGB、连续或明确标记缺失的深度数据重跑检测、ReID 与测距。
   只有 RGB 时，只评估视觉能力，不据此宣称验证了深度制动。
6. 复用现有异常触发机制，扩展到身份切换、反复左右摆动、纵向指令中断和人工接管，
   固定保留事件前后片段。重要片段另存，避免最近三次运行清理策略删除回归样本。

### 验收

- 同一记录及配置重复回放，决策和原因在约定容差内一致；回放不得初始化真实电机接口。
- 在每段固定视频上对比 UID 错误切换、重识别耗时、横向误差、左右反转次数。
- 在有完整距离与控制记录时，对比距离误差、无故零速次数、纵向指令连续性、样本过期后的撤销延迟。
- 离线记录只能验证记录场景中的决策变化，不能预测新动作导致的真实轨迹；闭环效果仍需实车复核。

## 2. 从目标居中扩展到整车通行判断

### Herbie 的设计

`evaluate_ribbon_candidate()`（476 行）把直行、左右弯曲的带状候选路径分为若干段，
逐段检查可行驶语义区域覆盖率；遇到第一段失败就终止有效延伸。
`get_candidate_rank()`（523 行）优先考虑连续有效段数等指标。
`build_candidate_band_cache()`（445 行）预计算固定几何，减少每帧重复工作。

可借鉴的直觉：目标在右边不等于车能直接向右走，需要检查车身将经过的整片区域。
这适合窄门、桌腿之间、转弯内侧和贴边跟随。

### 在本项目中的落地方式

- `config/reid_runtime.ini` 的 `[safety]` 已记录未来车宽/车长/边距参数，但注明尚未接入代码。
- 第一阶段用已有 Astra 深度，在相机标定和车体坐标下建立近场障碍区域，检查车身及转动扫过的空间。
  先作为通行检查模块，只输出左右/前方可用范围和限速、停止原因。
- 用现有目标方向生成少量候选运动，优先选择朝向同一目标且车体能通过的候选。
  保留目标身份；不可因为道路方向改变就更换跟随对象。
- 结果通过明确数据结构接入 `control_types.py` 与 `FollowSafetyController`，
  由 `MotionActionRuntime` 统一执行，不在路径模块直接发送串口命令。
- 红外等现有安全限制继续拥有最终否决权，受阻转向不能被改写为前进。
- 先以影子模式只记录建议与原因，核对窄通道和转弯片段，再接入低速控制。
- 若后续扩展到室外草地、路沿等场景，再评估语义分割数据、RKNN 部署和端到端延迟。
  Herbie 的 TensorRT engine 不能直接作为本项目 RKNN 模型使用。

### 不能照搬的参数

Herbie 的带宽、曲线和危险框主要是固定图像像素参数，不等于标定后的真实车宽。
我们是双轮差速底盘，需按本车运动学处理转弯与原地旋转，不能复制其舵机 PWM 映射。
深度无效区域应明确表示未知，不能自动认为畅通；地面、反光和缺测的处理需单独验证。

## 3. 统一人工接管与恢复流程

Herbie 的 `poll_controller()`（131 行）把手柄模式切换接到主循环，现场恢复很方便。
我们已有 `/home/topeet/lianzhan` 的键盘控制工具，但本次检查未发现活动跟随主循环中同等的统一手柄模式入口。

建议在现有动作执行器前统一管理 STOP / MANUAL / FOLLOW 权限：

- 接管时撤销旧自动动作及其版本，所有模式共用一个电机后端，避免两个进程争用串口。
- 按住允许运动、松开或输入过期归零；恢复跟随时重新检查目标身份和新鲜测距。
- 将模式切换及原因写入事件日志，可作为自动提取失败片段的标记。
- 手动命令仍经过既有硬停止和方向安全门。操作输入的读取应避免受推理耗时长期阻塞。

## 5. Herbie 中需要避开的实现问题

1. **固件超时不等于电机急停。** `src/arduino/Herbie.ino:185` 附近的 DEADMAN 只回正舵机；
   没有在命令失联时将左右 PWM 清零。Python `finally` 主动停车不能覆盖断电、进程强杀或串口断线。
   本项目已有 Python 动作过期停止，但驱动器失联是否自行停机仍需按 LZ30EMA 实际配置独立核验。
2. **视频回放未隔离执行器。** Herbie 的 `main()` 无条件调用 `open_port()`；回放模式仍可走电机发送路径，
   同时把危险标志设为 false。借鉴回放时必须改用独立虚拟后端。
3. **深度缺失当作无障碍。** `detect_obstruction_in_poly()` 没有有效深度时返回 false，不能把它当通行证明。
4. **帧数不等于时间。** 3 个坏帧和每帧油门增量随 FPS 改变实际保持时间、加速度。
   本项目应继续依据物理样本时间和单调时钟。
5. **阻塞影响响应。** Python `send_line()` 同步等待回执；Arduino 闪灯使用 delay 循环，
   这些会推迟后续处理。不要把此结构移植到当前动作调度中。

## 推荐顺序

1. **先做记录与控制级回放**：复用已有日志、CSV、深度快照和测试结构，优先复现当前跟随断续与转向问题。
2. **再做深度通行检查**：测量车体尺寸、核对相机标定，影子模式验证后再低速接入。
3. **统一人工接管**：接入同一动作仲裁和事件记录，缩短现场恢复时间。
4. **按场景需求增加语义分割**：先有本车视角数据和离线评估，再决定模型与算力投入。

改进效果需用固定场景对比验证；本次代码阅读不能得出实车稳定性或性能提升比例。
