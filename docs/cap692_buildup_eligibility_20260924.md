# CAP669–719：按实际制动量判断差速辅助资格

本轮未改轮差上限、纵向 PID、深度期限、身份阈值、驻车条件或电机参数，
没有启动相机、串口或操作实车。保留上一轮 CAP61 连续外移修复。

## 已修复

`image_brake_assist:taper` 只表示经过了预测制动计算，不保证实际削减了输出。
CAP692 的同类输入（误差约 -19.07°、车体 -6.27°/s、画面 -21.7°/s）
仍请求 -10 RPM；旧逻辑却仅凭标签禁止差速辅助。

- PID 新增 `position_demand_rpm` 和 `brake_reduction_rpm`，记录量化前的
  位置请求和实际制动削减量。削减量在小幅外移连续性恢复之前保存，不能
  因后续保留 2/4 RPM 而丢失原制动事实。
- 主程序发布资格与快环刷新资格共用 `steering_buildup_allowed()`。
  通过制动计算但削减为零的请求可以参加原辅助流程；即使削减不足 1 RPM、
  取整后请求仍相同，也不能放大。无数值证据时默认禁止，不凭旧标签批准。
- 中心保持、明确制动、反向制动、方向保护、早期外移 lead、贴边接续、
  驻车后低速接续仍不能获得增强资格。
- 原来的实际接近中心检查、两条独立的写入后反馈、采集时效、350ms 固定
  辅助窗口、前进授权、实际减速及反转保护继续生效，最后写入前仍复核。

注意：原 TurnBuildup 在窗口内可能暂时降低两轮共同前进量来建立差速。
本轮只是纠正该流程的入口，不提高上限、不延长窗口，也不消除该既有行为。

## CAP711 的核对与诊断

当时串口下发 -7/-7；按现有安装方向，物理前进归一后为 -7/+7，即左转，
没有发现这次请求被软件换算成右转。反馈读取使用带符号的速度寄存器；
左轮正、右轮负是前进归一后的结果，不能与串口原始正负号直接混用。

反馈 40/-7、随后 38/-5 是实际缓存内容，但旧日志没有保留这两次采样对应的
全部原始速度/位置字段，不能据此确定真实反转、控制器瞬态或采样问题。
本轮不翻转符号、不把异常反馈当作零、不忽略过零保护。

每条 `visible_wheel_dispatch` 追加缓存中的 `feedback_raw_rpm` 和
`feedback_position_deg`，与原有反馈时间、归一速度、此前指令及写入时间
一起记录。没有新增串口读取，也不等待新反馈。新日志可进一步对照位置变化
和速度符号；不能仅靠这个记录宣称硬件问题已解决。

## 验证范围

- CAP692 类数值路径及左右镜像：无实际削减的 taper 获准，真实削减仍拒绝。
- 覆盖不足 1 RPM 的削减、缺失/NaN 数据、反向输出、中心/身份相关受限路径。
- 真正的发布函数和快环：获准之后，一旦真实制动出现，同帧快环撤销增强资格。
- 真正的电机执行函数（假串口）：资格可到达有界辅助；原上限和保护不变。
- CAP711 类反向反馈仍使执行器输出零，并记录原始数据，不强制反转。

历史输入测试只能验证分支和下发，不代表实车已更快建立轮差。
