# 搜索模糊大框：有界零速观察

本次针对 195712 日志 CAP643/646/648/651。保持正常跟随 PID、ReID 身份阈值、
纵向控制和搜索方向策略不变，不进行实车动作。

## 搜索速度

主配置 `[motion] rotate_raw_target_search` 从 9 改为 7 RPM；
`[follow] search_candidate_acquire_raw_rpm` 同步从 8 改为 7，避免候选阶段反而提速。
无候选仍沿用 180ms 脉冲、4 RPM 同方向过渡，不增加每个脉冲都停车的等待。
实际角速度 10～15°/s 是下一轮验证目标，不是代码已保证的限速。

## 额外观察资格

旧门控返回 `candidate_already_observed` 时，以下证据可以申请一次重试：

- 连续两个不同的、新鲜采集帧；间隔不超过 250ms。
- 有唯一的有效正式 C0 检测候选，原始框与当帧 ReID 观测严格关联。
- 全身强库匹配当前活动 UID，距离不超过 0.30；仅局部特征不足以申请重试。
- 两帧框 IoU 至少 0.35、面积相似度至少 0.55；三边裁切本身不拒绝观察。
- 已排除的目标、多个人竞争、旧特征、碎框不获得额外窗口。

这里的 0.30 只允许**停车取证**，不是放宽身份确认阈值。
不输出 UID，不写身份库，不改变搜索方向，也不把重试完成算作身份确认。

## 窗口时序

同一搜索阶段、同一 UID 最多重试一次，raw track 切换不补充预算。
真正下发双轮 0 RPM 后记录首个成功写入时间，重复零指令不刷新该时间。
至少等到采集时间晚于该零速时间 80ms 的新帧才结束观察；这不是“机械惯性已完全消失”的证明。
最多 300ms，超时、候选消失/变化或竞争时退出，后续动作仍由原控制器决定。
旧帧只可作为诊断，不能靠重复处理完成本窗口。硬安全停车仍优先。

## 日志与验证

- `search_observation_retry`：起因、候选资格、采集时间、是否已消耗预算、截止时间。
- `search_observation_zero_sent`：零速请求和实际成功写入时间。
- `search_retry_post_zero_capture` / `search_retry_timeout`：观察完成方式，不代表身份成功。

下一轮比较搜索角速度、候选清晰度、成功接回耗时；检查每次搜索最多一个额外窗口，
没有候选时仍能扫描，前进不被本路径授权。切勿把合成离线测试当作实车改善结果。
如需单独回退新窗口，在主配置设置 `[follow] search_evidence_retry_enable=false`。
未显式开启此开关的其他配置保持原行为。
