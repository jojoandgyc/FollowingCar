# CAP74 / CAP96–108：纵向批准速度与转向差速解耦

依据 `run_20260923_221052_62510_1257852a`。本轮仅软件修改、无硬件测试。

## 新执行规则

正常差速前进采用前进归一化坐标：`L = B + Y`、`R = B - Y`。
`B` 是本次仍有效的纵向批准速度；`Y` 是通过当前视觉/转向限制的单轮修正值，总轮差为 `2Y`。
原始电机串口左右轴符号不同，不能直接将原始报文的两个数字相加求前进量。

移除三个转向策略对纵向的额外限制：

- 执行层不再调用 `limit_common_acceleration`，不再按“实测内轮+2”削掉两轮共同速度。旧配置开关即使为 true，也不能恢复此路径；启动日志明确记录 legacy_requested 和实际 enabled=False。
- `TurnResponseTrial` 不再保存或应用 `turn_finish_common_cap`。转向收尾、差速归零、轮速反馈未对齐，不能把新的纵向批准值锁在历史低值。
- `TurnResponseAssist` 的中心残余轮差分支不再限制纵向。增强逻辑只作用于差速。

物理轮速上限保持不变：优先限制差速余量。例如单轮上限200、纵向195、差速修正10，输出200/190，纵向仍为195。纵向达到200时已无差速余量；不会为了保留转向修正再压低纵向。显式更低的硬件执行上限仍可限制纵向本身。

短时反向差速用于抑制过转的证据检查及80ms限制仍保留；它不再顺便锁低前进量。危险、停车、近距离控制、身份失效、深度授权、实际下发前复核、换向和前进失权保护仍由原有独立路径执行。
