## 修改的边界

旧直接连续恢复仍保留；新增路径仅在 `depth_measured_recovery_enable` 开启时生效
（当前运行配置已开启）。不是删除安全停车，也不是持续执行过期指令。

1. 只有明确的框调度过期/同样本复用失败，才保存恢复参考；同UID仍可见、无搜索、
   无危险/障碍/制动/近距安全样本、无背景或跳变拒绝。参考最多保留500ms，重复尝试不续期。
2. **这500ms只是保存参考，不是授权期限。** 电机物理Depth TTL仍为180ms。
   必须重新取得新的、180ms内的可信目标Depth才允许恢复。
3. 新旧距离均>目标+0.30m，原始深度变化[-0.03,+0.30]m；明显靠近仍走旧严格路径。
   新反馈<=150ms、反馈与深度差<=150ms，双轮0..100RPM且角速度<=15°/s。
   危险、目标变化、搜索、反馈异常、零请求立即退出动态恢复。
4. 恢复第一张新样本用实测基速+50ms加速预算，不再要求达到原参考的90%。
   默认运行上升率240RPM/s，即首样本最多+12RPM；后续只按新物理样本间隔增加，
   每次计入最多100ms，且始终不超过实测基速+150ms预算、之前实际批准速度和当前请求。
   重复样本不能增加上限或延长计时。此动态恢复阶段最长400ms，之后回到正常PID限制；
   PID反饱和原有逻辑会将批准速度反馈为下一次slew的起点。
5. 恢复参考用真实经过质量限速的批准请求，不再借用更高的PID未批准请求。
   这是批准值，不是假定硬件已达到该速度，所以恢复仍要求实测轮速。

例：原批准55RPM、断档后实测40RPM，新请求70RPM，恢复上限先52，再随新样本升到55。
如果实际已停，先12RPM起步，不能瞬间回55；无新鲜深度仍为安全零输出。
身份、搜索、横向、轮周0.60m、匹配上限80、总上限200、积分与D均未修改。

## P 试验与运行

`FOLLOW_DISTANCE_P_TRIAL` 现在支持24/27/36，默认INI仍为24，必须显式选择36。
P36较24提高50%；误差0.5/1.0/1.5m时，单独P项分别多6/12/18RPM。
没有明显过冲支持做这个试验，但不能证明P就是唯一根因。

同一新代码做两轮，同路线、相近人速和起点，旁边有人急停；保持补偿都为5，
避免把本轮原先+5同时改成0，混淆P的作用：

```sh
# A：先验证恢复改动，保留上一轮P与补偿
FOLLOW_DISTANCE_P_TRIAL=24 FOLLOW_MATCHING_BIAS_TRIAL=5 ./run_request_0428_modular.sh
# B：只改变纵向P，明确测试更强的距离修正
FOLLOW_DISTANCE_P_TRIAL=36 FOLLOW_MATCHING_BIAS_TRIAL=5 ./run_request_0428_modular.sh
```

可以直接先试B，但它与旧版的差异包含恢复改动，不能把改善全归因于P。
出现更大过冲、振荡或错误测距追赶就结束测试，P恢复24；不要同时增加匹配/总上限。
继续标注移动开始/结束CAP。日志只保留最近三轮，及时保留所需对照素材。
